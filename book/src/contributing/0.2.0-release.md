# Wisp 0.2.0 release decision and checklist

Status: release preparation, October 18, 2026. This PR prepares the release; it does not create
`v0.2.0` or publish packages. At preparation time, RC13 (published October 18, 2026) is the latest
candidate, and 0.1.0 is the latest stable release. The [RC13 checklist](./rc13-release) records the
decisions 0.2.0 keeps.

## Release decision

0.2.0 promotes RC13 to the second stable release. It keeps RC13's platforms (native wheels for
macOS arm64 and Linux glibc 2.28+ x86_64, plus a pure wheel) and every command, event, handshake,
session, settings, and trust format. The version is `0.2.0` in both the Python and the Cargo files.

Since RC13 it contains:

- **No bundled `github-pr-delivery` skill** (#748). Only `wisp-development` (1.5) ships; a user or
  project skill with that name is unaffected.
- **The refreshed startup logo and brand images** (#740).
- **Repository, docs, and packaging changes** with no runtime effect (#741–#747): the book in
  `book/`, benchmark evidence in `benchmarks/evidence/`, `packaging/hatch_build.py`, deduplicated
  images, `CONTRIBUTING.md`, `SECURITY.md`, and a new README.

The stable install commands now install 0.2 (`uv tool install --python 3.12 wisp-ai`), and the
[upgrade guide](../guide/upgrading) covers moving from 0.1.0 and going back to it.

Not in 0.2.0: HY-266 (Google search), HY-261 and HY-264 (`/mcp` conveniences), HY-253 (PTY approval
test), HY-254 (`edit` diff line numbers), HY-289 (further resume cuts), and HY-29 (macOS handoff test
flakes).

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python formatting, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] The dependency-drift workflow passes on the newest allowed dependencies.
- [ ] Rust formatting, Clippy, workspace tests, build, and the Python/Rust handoff and benchmark PTY
  tests pass. The macOS handoff step still runs with `continue-on-error` (HY-29); check its failure
  annotations.
- [ ] `mdbook build book` succeeds without logged errors.
- [ ] The release workflow's dry run verifies version parity, one sdist, one pure wheel, two native
  wheels, wheel content parity, checksums, SBOMs, and the live RPC schema bundle, and classifies
  `0.2.0` as not a prerelease.

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.2.0` tag through the existing
release workflow. Because `0.2.0` is not a prerelease, the GitHub release is created as a normal
release and PyPI's default install moves from 0.1.0 to 0.2.0.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes, and
  `gh attestation verify` succeeds for each.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on each claimed
  native target installs the native wheel: `wisp --version` and `wisp-tui --version` both report
  `0.2.0`.
- [ ] An unpinned `pip install wisp-ai` in a clean Python 3.12 environment resolves `0.2.0`.
- [ ] `wisp skills` lists only `wisp-development`.
- [ ] With a stdio MCP server configured, the published install starts it and registers its tools.
  Record the `mcp` version the install resolved.
- [ ] The pure wheel in a clean environment: print, JSON, SDK, and RPC work; interactive `wisp`
  reports the actionable missing-TUI error.

## Upgrade from 0.1.0

- [ ] Starting from a published 0.1.0 `uv tool` install with a saved credential, settings, and a few
  sessions, the upgrade command in the upgrade guide installs 0.2.0; the credential still works,
  and 0.1.0 sessions resume.
- [ ] A `catalog.toml` overlay without `schema_version = 2` reports a clear error.

## Real-terminal dogfooding

- [ ] The startup logo renders at the default size and collapses cleanly in a short or narrow
  terminal.
- [ ] A streamed reply finishes without the transcript jumping, and resuming a long saved session
  keeps every earlier prompt reachable by scrolling.
- [ ] Approvals, cancellation, steering with `Enter`, follow-ups with `Alt+Enter`, `/search`, and
  `/mcp` behave as in RC13.

## Rollback

If 0.2.0 regresses, exit Wisp and follow [Going back to 0.1.0](../guide/upgrading#going-back-to-010):
remove hosted MCP servers from `settings.json` and home-folder trust records first, then
`uv tool install --force --python 3.12 "wisp-ai==0.1.0"`. 0.1.0 reports sessions holding 0.2-only
records as malformed (verified for a trusted project's Git snapshot); back up sessions and start new
ones. To return to the last candidate instead, install `wisp-ai==0.2.0rc13`, which reads every 0.2.0
session.
