# Wisp 0.3.0 release decision and checklist

Status: release preparation, October 23, 2026. This PR prepares 0.3.0; it does not create
`v0.3.0` or publish packages. The latest published stable release is 0.2.4 (October 20, 2026).

## Release decision

0.3.0 is a minor feature release on 0.2.4. The terminal redesign, working-tree diff review,
source-attributed context, durable tool/run timing, and shared response guidance form one
user-visible milestone. The [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md)
records the net changes, including the additive RPC and event contract updates.

Python distribution/runtime, Rust TUI, and native Python extension versions are all `0.3.0`.
Internal helper crates retain their independent versions. Native targets remain macOS arm64
and Linux glibc 2.28+ x86_64; other platforms retain the pure wheel. Python 3.12+ is required.

## Compatibility decision

- The backend, TUI, and external RPC client must come from the same Wisp release. No mixed-release
  compatibility is introduced. The 0.3.0 schema bundle includes `get_git_diff`, `rpc.git_diff`,
  `rpc.workspace`, context attribution, and tool/run/history metadata.
- 0.3.0 reads 0.2.4 sessions. The session-entry, event-envelope, and compaction stamps remain
  v6, v1, and v4 because new fields have defaults and require no migration.
- 0.2.4 may reject sessions written by 0.3.0 when the new tool metadata is present; typed event
  access also rejects unknown fields. Back up sessions before upgrading and keep the backup
  separate. Rollback uses that backup or new sessions, preserving 0.3.0-written files for 0.3.0.
- Settings, credentials, and trust formats are unchanged. No documented Python API removals
  accompany this release. See [Upgrading to 0.3](../guide/upgrading-to-0.3.md).

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and live RPC schema checks pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The release dry run succeeds on the accepted commit, including macOS arm64 and
  manylinux_2_28 x86_64 candidate wheels, installed-wheel checks, and install lifecycle tests.
- [ ] The dry run verifies four distributions (sdist, pure wheel, two native wheels), version
  consistency, checksums, SBOMs, install evidence, and the live RPC schema archive.
- [ ] mdBook and Astro builds pass, including preserved routes and browser checks.
- [ ] In a real terminal, inspect the sidebar inventories, prose/list spacing, `/diff`, retained
  edit review, process output folding, and resize behavior in dark and light themes.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref codex/release-0.3.0
```

A branch dispatch builds and validates artifacts. Attestation, PyPI publication, and GitHub release
creation are tag-gated and intentionally skipped. Record the run URL and tested commit in the PR;
any code change after a successful run needs fresh evidence for the changed release candidate.

## Publication and public-install acceptance

After the preparation PR merges and acceptance is complete, publishing requires a separately
authorized `v0.3.0` tag through the release workflow. Version 0.3.0 is not a prerelease, so normal
PyPI installation will move from 0.2.4 to 0.3.0 when it is published.

- [ ] The tag points to the accepted commit; all release jobs succeed, including attestation,
  publication, and GitHub release creation.
- [ ] PyPI and the GitHub release contain the four distributions with matching SHA-256 hashes.
- [ ] A clean Python 3.12+ install outside the checkout reports `0.3.0` from both `wisp --version`
  and `wisp-tui --version` on each native target, without requiring Cargo.
- [ ] Verify representative 0.2.4 sessions can be resumed after upgrade; preserve the original
  copies for rollback and do not claim that 0.2.4 reads newly written metadata.

## Rollback

Follow [Going back to 0.2.4](../guide/upgrading-to-0.3.md#going-back-to-024). Reinstall the matched
0.2.4 package, use pre-upgrade session copies or new sessions, and retain any files written by
0.3.0 for use with 0.3.0. Do not strip unknown fields from session files.
