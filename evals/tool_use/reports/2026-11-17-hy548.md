# HY-548: persistent script state pilot

The candidate completed all six multi-prompt scenarios and reused persisted data after
compaction and backend restart without fetching it again. This demonstrates the capability
on one synthetic task; it does not establish a general reliability or efficiency advantage.
Current codemode also completed all six controls. Defaults remain unchanged.

## Contract and acceptance, set before the pilot

Scripts have `await store(key, value)`, `await load(key)` and `await delete(key)` for bounded
JSON. A script stages private changes; only success can publish them. CodingSession attaches
one full changed snapshot to that script's successful result entry. Failed/cancelled scripts
and synthetic cancellation repairs attach none. State follows the active session tree path,
not provider context rows, so compaction does not depend on the summarizer reproducing data.

Limits: 128 keys, 128 UTF-8 bytes per non-empty key, 64 KiB per value, 256 KiB per complete
store (compact UTF-8 JSON), and 32 nested containers. State helpers share the script's external
call budget. Copies cross store/load boundaries. Concurrent standalone read-only scripts
remain supported; conflicting changed transactions fail instead of losing writes. Production
codemode calls remain serialized. Active-state quotas do not cap the append-only audit log.

Primary live acceptance is the entire `mcp-session-reuse` scenario passing: fetch the complete
open-PR dataset, acknowledge a follow-up, compact, restart/resume, then perform the exact
approved answer-file write. The final answer must include all seven matching records. No
judge model is used. Secondary observations are saved snapshots, post-resume fetches, script
errors, token accounting, estimated cost and latency. Prompts permit direct tools or scripts;
none forces a codemode call. Missing/wrong approval arguments fail even if a plausible file
could otherwise have been written.

## Setup

- Baseline source: `dcdc9ac107e07a7a55d2b68b6e20bce7a5fcdd1e` (merged HY-547), Wisp 0.12.0.
- Candidate: that commit plus the HY-548 source changes. Result rows record `-dirty` because
  implementation was evaluated before a delivery commit.
- Candidate source fingerprint: `75f7fd8a372da585f7ab60016d50a3feebc42457dcc1ecb275e6795c7e011b42`.
  Hash the sorted relative names and bytes of `src/wisp/coding/{script_state,session}.py`,
  `src/wisp/sessions/{entries,replay}.py`, and
  `src/wisp/tools/codemode/{state,tool,sandbox}.py`, prefixing each name and contents with its
  8-byte big-endian length, then SHA-256 the concatenation.
- Models: `openai-codex::gpt-5.6-luna` and `anthropic::claude-sonnet-5-5`, both requested effort
  `medium`; three repetitions per model/arm. No Gemini calls.
- Arms: codemode off on the baseline; current read-only codemode on the baseline; candidate

- `mcp_tool_exposure=on_demand`, `mcp_results=structured`; built-ins `read` and `write`.
  Real scripted approvals, no `--yes`; one exact approved write at the end.
- Whole-scenario timeout 300 seconds, 15 tool iterations per prompt, default output/script
  limits. Two model runs in flight per arm. Off/current order alternates between repetitions;
  the candidate ran separately and overlapped later control runs, not a fully interleaved trial.
- Shared pilot ceiling: $6 priced API usage and 1.5M tokens, checked between rounds. Total

  GPT subscription usage is unpriced, not free. Provider-normalized token use, including cache

- Task, fixture and catalog fingerprints, requested effort, step counts, cache usage and costs

Every candidate run made one dataset fetch, saved one snapshot, and used `load` after resume.
Fetch counts include top-level and nested dataset calls, not just outer codemode calls.
Whole-run fetch differences also reflect pagination choices, so they are not entirely caused
by persistence. Some controls answered correctly from summaries without another fetch.

The failed GPT-off run attempted to write `503,509,525,530,533`, omitting 508 and 528. Its exact
approval check denied the write and stopped the scenario; it was retained as a task failure.
No scored runs were silently retried. Claude produced four failed scripts across current
codemode runs and two across candidate runs, then recovered; failures remain in the baselines.

Mean durations were GPT 50.1/57.6/45.1 seconds and Claude 30.5/32.2/29.1 seconds for
off/current/state respectively. These are descriptive only: concurrent runs, cache order,
provider load and the small sample prevent a causal latency claim. Candidate Claude used more
tokens and cost more than codemode off, despite needing fewer fetches. Do not treat the pilot
as evidence for enabling codemode everywhere or changing defaults.

### Launcher errors retained separately

The first two off-arm traces reached all five scenario steps successfully, but the temporary
pilot launcher passed a file handle where `write_row` requires a path. Their original wall
measurements were lost. Recovered usage and raw traces are retained in the `hy548-harness-errors`
baseline as **errored**, with `seconds=0` meaning unavailable, and excluded from every table
above. Their estimated API spend ($0.0618799) and tokens are included in the shared totals.
The launcher was corrected before collecting the three scored repetitions. No failed model
sample was replaced.

## Reproduce and inspect

On each selected build, with the identical task fixture available, the normal runner command is:

```bash
uv run python -m evals.tool_use run --tasks mcp-session-reuse \
  --models openai-codex::gpt-5.6-luna,anthropic::claude-sonnet-5-5 \
  --effort medium --reps 3 --workers 2 --mcp-tool-exposure on_demand \
  --mcp-results structured --codemode python --budget-usd 6 --budget-tokens 1500000
```

Use `--codemode off` for the off arm and enforce the shared budget across arms. The recorded
pilot used `run_one` with the same RunContext settings to alternate off/current order; its
baseline launcher imported source extracted with `git archive` from the baseline commit.
The candidate used the checkout executable. No dependencies or runtime settings were changed.

## Deterministic evidence and limits

Actual Monty tests cover copies, strict JSON, quotas, deletion, failed scripts, timeouts,
cancellation, callback failures, helper-name collisions and conflicting concurrent commits.
CodingSession tests cover result/state co-persistence, restart, branch navigation, clone
isolation, compaction, cancellation, lost append receipts and stale session writers. Independent
read-only review found no actionable issues. Exact cancellation in the post-script/pre-terminal
handoff was inspected in source; it is not a separately injected regression.

This is one synthetic data-reuse task on two models. It does not establish behavior on very
large stores, long-lived histories, real changing MCP data, Windows, or mutating tools. The
candidate adds persistence while retaining the existing read-only nested-tool policy. Artifacts,
mutations, broader discovery and rollout/default decisions remain separate HY-546 work.

## Implementation verification

Commands used the existing environment with `UV_CACHE_DIR=/tmp/wisp-uv-cache uv run --no-sync`.
No packages, toolchains or browser bundles were installed.

- `ruff format --check .`, `ruff check .`, configured `mypy` (266 source files), live RPC
  schema check and `git diff --check` passed. No live event/protocol model changed. The new
  session-entry field is optional, so old current-version sessions remain readable without
  a session-schema bump.
- The tool-side focused suite passed 195 existing/new codemode tests. There are 44 new state
  and integration cases, including parameterized cases. The integration tests alone passed
  all 10 cases. Documentation/repository checks passed 187 tests.
- Broad parallel command: `pytest tests -n 4 -m 'not (slow or process or benchmark)' -q`:
  5,508 passed, 19 failed, 4 skipped. One failure was the documentation test's former
  single-example assumption, fixed by executing both examples (3 guide tests pass). The other
  18 were sandbox restrictions on OAuth loopback listeners and filesystem operations; all
  passed in a targeted 69-test rerun outside the sandbox.
- Broad serial command: `pytest tests -m 'slow or process or benchmark' -q`: 345 passed,
  7 failed, 52 skipped. The seven socket/process-inspection restrictions passed in the
  outside-sandbox targeted rerun (12 parameterized cases). No unresolved Python test failure
  remains from these runs; the full suites were not redundantly rerun outside the sandbox.
- Scoped `crapper --no-coverage` and `dryer` reviews completed. Existing large orchestration
  functions remain largely unchanged; no new equivalent-logic duplication warranted extraction.
  Coverage and mutation tooling were skipped because coverage was unavailable, per the
  quality-gates workflow. Independent review found no actionable issue.
- Documentation build and output-link validation passed. `npm run verify:browser` could not
  complete: the sandbox blocked its listener; outside it, an unrelated server occupied the
  hard-coded port 4322. An alternate-port attempt also found the pinned Chromium bundle missing.
  Installed Chrome could run tests, but the suite's hard-coded 4322 URLs prevent using that
  alternate port consistently. No unrelated server was stopped. A focused existing-Playwright/
  installed-Chrome check of the changed section on port 4323 passed at 1440px and 390px in
  light/dark themes, with screenshots inspected, no horizontal page overflow and no browser
  errors. The full browser suite remains unverified in this environment.
