# Wisp 0.14.1 release decision and checklist

Status: release preparation, November 19, 2026. This PR prepares the release; it does not create
`v0.14.1` or publish packages. 0.14.0 (published November 19, 2026) is the latest stable release.

## Release decision

0.14.1 is a patch release on 0.14.0. Supported platforms stay unchanged: Python 3.11+, native
`cp311-abi3` wheels for macOS arm64 and Linux glibc 2.28+ x86_64, plus the pure fallback wheel and
source distribution. The Python distribution/runtime, Rust TUI, and native Python extension use
`0.14.1`; the existing backend/frontend version check continues to require a matching release.

It carries three user-facing changes:

- **Gemini 4 Neon (#1079).** `gemini-4-neon` joins the catalog for the `google` provider with
  image input, a 1,048,576-token context window, `LOW`/`MEDIUM`/`HIGH`/`XHIGH` thinking levels
  with `HIGH` as the default, and standard prices of $3 input, $0.15 cached input and $15 output
  per million tokens. The default model and older entries are unchanged.
- **Background processes in fewer TUI places (#1078).** The status line no longer names a
  background process, the strip under the composer hides beside a docked side panel, the docked
  panel lists only processes that are running or went wrong, and adjacent clean exits fold into
  one `Background N commands · passed` transcript row. A process row the `start` call did not
  label takes the command from its `process.ended` event.
- **Footer notices expire (#1080).** A notice is dismissed after 8 seconds, or after one full lap
  of its ticker when it is too long for its row, instead of staying until the next edit or
  prompt. The event loop sleeps until the notice's deadline, so this also happens while idle.

**Why a patch.** No command, event, handshake, session, settings, credential, or trust format
changes, and the live RPC schema bundle is unchanged, so 0.14.0 and 0.14.1 read each other's
sessions. The supported Python API is unchanged. 0.9.1 added a catalog model the same way.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.
This PR also dates the 0.14.0 changelog heading, which 0.14.0's own checklist left open.

Known limitations:

- **Gemini 4 Neon was not called live.** Its entry comes from Google's model page, thinking guide
  and pricing page. That the API accepts `XHIGH` and rejects `MINIMAL` for it is documented, not
  observed.
- **Only back-to-back clean exits fold.** A process row sits where its exit arrived, so a clean
  exit between tool rows keeps its own row.
- **Resumed sessions keep unlabelled process rows.** History replays no `process.ended`, so a row
  with no label there still reads `Background command`.
- **A repeated notice keeps its first deadline.** The clock restarts only when the notice text
  changes.
- **Compaction warnings do not expire.** They stay until the next prompt or compaction, as before.
- **The idle expiry has no loop-level test.** Unit tests cover the deadline and the dismissal; the
  event loop waking on that deadline is covered only by the real-terminal check below.

## Prepublication acceptance

Record CI and dry-run links in the preparation PR; unchecked items below remain publication gates.

- [ ] The exact preparation PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] Astro format/type checks, tests, build, and release-route browser checks pass.
- [ ] Candidate wheels pass on macOS arm64 and manylinux x86_64, including installed-wheel smoke
  and exact Python/TUI/native-extension version consistency.
- [ ] The release dry run succeeds on the accepted commit and verifies all four distributions.

The existing workflow's manual dispatch performs a dry run without publishing:

```bash
gh workflow run release.yml --ref chore/release-0.14.1
```

## Publication and public-install acceptance

After this preparation PR merges, publication requires a separately authorized `v0.14.1` tag
through the existing release workflow. PyPI's default install moves to 0.14.1 after publication.

- [ ] The tag points to the accepted commit and all release jobs succeed, including attestation,
  PyPI publication, and GitHub release creation.
- [ ] PyPI and GitHub contain the expected four distributions and matching SHA-256 hashes.
- [ ] Outside the source checkout, fresh Python 3.11 and 3.12 native installs report `0.14.1`
  from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, pick a model with `/model` and leave the keyboard alone: the footer
  notice disappears after about 8 seconds.
- [ ] In a real terminal wide enough to dock the side panel, have the agent start two background
  commands: the panel lists them, no strip shows under the composer, and the status line names no
  `Process`. After both exit cleanly one after the other, the transcript shows one
  `Background 2 commands · passed` row.
- [ ] With a Google API key, `/model` lists `gemini-4-neon`, and a prompt on it completes and
  reports a cost. Update the catalog comments if the thinking levels differ from the docs.
- [ ] Replace `0.14.1 — Unreleased` in the changelog with the publication date and preserve the
  old heading anchor, following earlier release entries.

## Rollback

0.14.0 and 0.14.1 read each other's sessions. To go back, install `wisp-ai==0.14.0` with the
desired existing extras; both `wisp` and `wisp-tui` must report `0.14.0`. 0.14.0 passes
`gemini-4-neon` through to Google as an uncatalogued model, so a session that selected it keeps
working without its cost shown. Nothing on disk needs cleanup.
