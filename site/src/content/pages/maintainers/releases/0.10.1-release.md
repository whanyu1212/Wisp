# Wisp 0.10.1 release decision and checklist

Status: release preparation, November 15, 2026. This PR prepares the release; it does not create
`v0.10.1` or publish packages. 0.10.0 (published November 14, 2026) is the latest stable release.

## Release decision

0.10.1 is a patch release on 0.10.0. It keeps the platforms from the
[0.8.0 checklist](0.8.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
tagged `cp311-abi3`, plus a pure wheel; Python 3.11+ is required. The Python distribution/runtime,
Rust TUI, and native Python extension use `0.10.1`; the existing backend/frontend version check
continues to require a matching release.

It carries one user-facing change:

- **A second `Ctrl+C` while quitting no longer ends the backend (#1021).** Quitting the terminal UI
  restored the terminal before the backend had finished shutting down, which takes about 0.3
  seconds. A second `Ctrl+C` in that time was no longer a key press: the terminal sent an
  interrupt to the backend, which ended before it had cleaned up, and Wisp printed
  `backend exited unsuccessfully with signal: 2 (SIGINT)` and exited with status 1. The terminal
  UI now keeps `Ctrl+C`, `Ctrl+Z` and `Ctrl+\` from sending signals until the backend has exited.

#1018–#1020 change the documentation site only and do not change the packages' behavior.

**Why a patch.** No command, event, handshake, session, settings, credential, or trust format
changes, and the live RPC schema bundle is unchanged, so 0.10.0 and 0.10.1 read each other's
sessions. The supported Python API is unchanged.

**Why now.** 0.10.0 has the fault on `Ctrl+C`, the usual way to quit, and a backend that is
interrupted skips its cleanup.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

Known limitations:

- **The signal keys do nothing while the backend shuts down.** A shutdown that hangs cannot be
  interrupted from the keyboard. The existing shutdown timeouts end it after about 10 seconds at
  most.
- **Input typed while quitting is discarded,** so a stray `Ctrl+C` does not reach the shell. A
  command typed in that time is lost too.
- **Standard input that is not a terminal keeps the old behavior.** The fix reads the terminal's
  settings from standard input.
- **`wisp-tui` run by itself.** If it is killed while the backend shuts down, the shell is left
  with the signal keys off until `stty sane`. Under `wisp` the launcher restores the terminal.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.10.1
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.10.1` tag through the
existing release workflow. Because `0.10.1` is not a prerelease, PyPI's default install moves to
0.10.1.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.10.1` from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal on macOS and on Linux, quit `wisp` by pressing `Ctrl+C` several times
  quickly: it prints no error, `echo $?` reports 0, and `Ctrl+C` works at the shell prompt
  afterwards.
- [ ] Replace `0.10.1 — Unreleased` in the changelog with the publication date.

## Rollback

0.10.0 and 0.10.1 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.10.0"`; both `wisp` and `wisp-tui` must report
the same release. Nothing on disk needs cleanup.
