# Wisp 0.15.0 release decision and checklist

Status: release preparation, November 21, 2026. This PR prepares the release; it does not create
`v0.15.0` or publish packages. The previous stable release is 0.14.2, published November 20, 2026.

## Release decision

0.15.0 is a minor release on 0.14.2. The Python distribution/runtime, Rust TUI, and native Python
extension all use `0.15.0`. Supported platforms stay unchanged: Python 3.11+, native `cp311-abi3`
wheels for macOS arm64 and Linux glibc 2.28+ x86_64, plus the pure fallback wheel and source
distribution. The backend and frontend must be the same release.

The changes since `v0.14.2` (`#1087`–`#1109`) deliver the embedded interactive live browser,
inline transcript thumbnails, a redesigned live-work side panel, prompt-scoped session sharing,
and scoped external reads in `Auto commands`:

- **Embedded interactive live browser with agent awareness (#1098–#1104, #1106–#1109).** Adds
  the `/browser` side-panel view with Kitty `U=1` (and iTerm2/Sixel/halfblock fallback) live
  viewport rendering, centered overlay expansion, MCP takeover, interactive isolated Chromium
  tabs with high-DPI capture and navigation, a start page with address/search input
  (`browser_search_engine`, `get_browser_addresses` / `rpc.browser_addresses`), persistent
  cookies/sign-ins under protected `~/.wisp/browser-profile` (`wisp browser clear`), waiting
  `live_frame` streaming, coalesced wheel input with 60 Hz Chromium `requestAnimationFrame`
  ease-out smooth scrolling (supporting Shadow DOM, same-origin iframes, negative-range
  `column-reverse`/RTL containers, and CDP `mouseWheel` fallback), draggable dock-border
  resizing with OSC 22 `ew-resize` cursor support including Rex (`REX_SESSION`), and agent
  live-browser tools (`browser_navigate`, `browser_read`, `browser_click`, `browser_type`,
  `browser_screenshot`) governed by `browser_default` / `WISP_BROWSER_DEFAULT`.
- **Inline transcript thumbnails and live-work side panel (#1093, #1097, #1104).** Renders
  aspect-preserving inline thumbnails beneath `[image ...]` labels (`tui_images` /
  `WISP_TUI_IMAGES`) using `O_NOFOLLOW | O_NONBLOCK` reads and `rpc.workspace.session_images_dir`,
  redesigns the side panel around live approvals/plan/processes, and moves `Work`/`Browser` tabs
  into an always-visible one-row top bar (minimum terminal size `30x9`).
- **Share saved sessions with the next prompt (#1095).** `/past-sessions` lets users share one
  saved conversation with the next prompt via `read_only` `get_sessions`, `saved_session_id` on
  `prompt`, and bounded `read_saved_session` excerpts without mutating or leaving the active
  session.
- **Scoped external reads in Auto commands, docs, and CI (#1087–#1092, #1094, #1096, #1105).**
  Adds `--auto-command-read-dir` / `InProcessOptions.auto_command_read_dir` for bounded macOS
  Seatbelt external reads, fixes macOS zombie `EPERM` foreground cleanup and editor draft teardown
  ordering, refreshes the Astro homepage around personal software framing, and parallelizes Python,
  Rust, and release CI workflows.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md).

**Compatibility:** session `schema_version` 6 and event-envelope format 1 are unchanged, and no
new persisted session entry fields are added, so `0.15.0` and `0.14.x` read each other's sessions.
New user-only settings (`tui_images`, `browser_search_engine`, `browser_default`) are ignored by
`0.14.x`. The live RPC bundle (`schemas/live-rpc/` and conformance fixtures) adds
`browser_interact`, `get_browser_addresses`, `browser.viewport.updated`, `rpc.browser_addresses`,
`rpc.workspace.session_images_dir`, `prompt.saved_session_id`, and `get_sessions.read_only`.
Backend, frontends, and external RPC clients must match `0.15.0`.
See [compatibility](../../reference/compatibility.md#wisp-015-compatibility).

Known limitations:

- **Embedded Chromium tabs require a local Chromium/Playwright browser and trusted project.**
  Untrusted projects refuse live browser launches (`get_browser_addresses` returns empty when
  untrusted), and systems without a compatible Chrome/Chromium binary stay on MCP or fail with an
  explanatory error.
- **Graphics and pointer protocols depend on terminal support.** Kitty `U=1` image reuse
  activates on supported Kitty/Ghostty-class terminals outside tmux, falling back to iTerm2,
  Sixel, or Unicode half-blocks elsewhere. Dock-border `ew-resize` OSC 22 sequences are sent only
  to kitty, Ghostty, foot, and Rex outside tmux, provided `?1003` mouse motion capture is active.
- **Real-terminal visual, scrolling, and Rex cursor verification remain manual gates.** Automated
  unit, conformance, render-buffer, and Chrome PTY E2E tests cover logic and rendering paths,
  while visual responsiveness in Rex/Ghostty/Kitty remains a manual acceptance check below.

## Prepublication acceptance

Record CI and dry-run links in the preparation PR; unchecked items below remain publication gates.

- [ ] The exact preparation PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] Astro format/type checks, tests, build, and release-route browser checks pass.
- [ ] Candidate wheels pass on macOS arm64 and manylinux x86_64, including installed-wheel smoke
  and exact Python/TUI/native-extension version consistency.
- [ ] The release dry run succeeds on the accepted commit and verifies all four distributions.

The existing workflow's manual dispatch performs a dry run without publishing:

```bash
gh workflow run release.yml --ref chore/release-0.15.0
```

## Publication and public-install acceptance

After this preparation PR merges, publication requires a separately authorized `v0.15.0` tag
through the existing release workflow. PyPI's default install moves to 0.15.0 after publication.

- [ ] The tag points to the accepted commit and all release jobs succeed, including attestation,
  PyPI publication, and GitHub release creation.
- [ ] PyPI and the GitHub release contain the expected four distributions and matching SHA-256 hashes.
- [ ] Outside the source checkout, fresh Python 3.11 and 3.12 native installs report `0.15.0`
  from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal (including Rex), verify live browser opening from the `Browser` tab,
  60 fps smooth scrolling, dock-border resize cursor/drag reflow, inline transcript image
  thumbnails, `/past-sessions` attachment, and clean mouse/pointer reset on exit.
- [ ] Replace `0.15.0 — Unreleased` in the changelog with the publication date, keep the old
  `0150--unreleased` heading anchor, and add it to `site/tests/browser/releases.spec.ts`.

## Rollback

Install `wisp-ai==0.14.2` with the desired existing extras; both `wisp` and `wisp-tui` must report
`0.14.2`. `0.15.0` and `0.14.x` read each other's sessions, and `0.14.2` ignores `tui_images`,
`browser_search_engine`, and `browser_default` in `~/.wisp/settings.json`. Use the `0.14.2` live RPC
schema bundle for external RPC clients. Run `wisp browser clear` before downgrading if you want to
remove saved `~/.wisp/browser-profile` state.
