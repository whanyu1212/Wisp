# Wisp 0.11.0 release decision and checklist

Status: release preparation, November 16, 2026. This PR prepares the release; it does not create
`v0.11.0` or publish packages. 0.10.1, published November 15, 2026, is the latest stable release.

## Release decision

0.11.0 is a minor release on 0.10.1. It keeps the platforms from the
[0.8.0 checklist](0.8.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
tagged `cp311-abi3`, plus a pure wheel; Python 3.11+ is required. The Python distribution and
runtime, the Rust TUI, and the native Python extension all use `0.11.0`. The existing
backend/frontend version check still requires a matching release.

It carries 18 merged pull requests (#1024–#1041). The main changes:

- **Codemode scripts work with more of each result (#1029, #1038, HY-511, HY-512).**
  - **Full results:** a script's tool calls return up to 512 KiB of each result instead of the
    model's 50 KB cut. A result cut short ends with `[result incomplete]`.
  - **Typed results:** an MCP tool that declares an output schema returns its structured result
    as a typed dict. A script reading a field the schema lacks fails its type check before it
    runs.
  - **What stays the same:** direct calls, subagents, events and sessions still see only text.
- **Failed calls no longer end a script (#1027, #1036, HY-515, HY-545).** `gather_settled` runs
  calls at once and returns every outcome in order, a failed call's error in place of its
  result. Only the run's own failed tool calls come back this way.
- **When automatic codemode is offered (#1025, #1041, HY-510, HY-431).** With `codemode` unset,
  it is offered whenever a script may call one of the run's MCP tools: marked `"read"` in its
  server's `tool_safety`, found on demand or sent directly. Before, it needed on-demand
  discovery, and it was offered even when every MCP tool was a command tool, so every script
  call to one was refused. A run with only built-in tools still goes without.
- **Read-only MCP tools in the terminal UI (#1026, #1032, #1034, HY-510).**
  - `/mcp` shows how many of each server's tools are read-only.
  - `/mcp` marks with `hint` the tools a server says are read-only but `tool_safety` leaves
    unset, and `h` offers to mark them, up to 8 at a time. The hint alone changes nothing.
  - `/codemode` says how many MCP tools a script can call.
- **Background processes in the terminal UI (#1028, #1030, #1033, #1035, HY-492, HY-542,
  HY-543, HY-544).**
  - A strip under the composer lists running processes, even with the side panel hidden.
  - Enter on a process in the side panel shows its latest output in place, and `x` then `y`
    stops it.
  - Ended processes stay listed with how they ended.
  - A `bash` poll of a process the user stopped says so, so the agent does not restart it
    unasked.
- **Fixes (#1031, #1041, HY-501).**
  - `import wisp.images` works as a program's first Wisp import.
  - An in-process SDK shutdown test no longer fails on a loaded machine.
- **Evals (#1024, #1039, #1040).**
  - Reports count tokens the same way across providers and estimate Codex costs.
  - Baselines record why scripts failed and how many calls each failed script made.
  - The devhub eval tools can return structured results.

**Why a minor release.** The wire contract grows:

- **New commands:** `get_processes`, `get_process_output` and `mark_mcp_tools_read_only`.
- **New events:** `rpc.processes` and `rpc.process_output`.
- **New required fields:**
  - `CodemodeState` gains `mcp_tools` and `scriptable_mcp_tools`;
  - MCP server snapshots gain `read_only_tool_names` and `read_only_hint_tool_names`.

A 0.10 reader rejects each of them, and the connect-time version check already refuses a mixed
backend and frontend. Session files keep `schema_version` 6; see [Rollback](#rollback).

**Codemode is offered in more runs.** With the `codemode` extra installed and `codemode` unset, a
run that sends read-only MCP tools directly now offers the `codemode` tool. Its description adds
about 1.3k tokens to every request in those runs, mostly cached. Two eval results back this:

- **MCP tools sent directly (2026-11-10):** codemode raised luna from 15 to 24 of 25
  orchestration runs.
- **Typed results (2026-11-16, 150 runs):** small gains, with no regression.

`"codemode": false` or `WISP_CODEMODE=0` turns codemode off. Installs without the extra are
unaffected.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

Known limitations:

- **Not tried by hand.** The terminal UI changes in #1026, #1028, #1032, #1034, #1035 and #1037
  had no manual terminal check before this preparation; the acceptance list below covers them.
- **Some calls still return text to a script.** `mcp_call` inside a script, and an MCP tool whose
  name is not a Python identifier, return text even when the tool has a structured result.
- **`integer` fields** are typed `int`, though JSON Schema also accepts a value such as `7.0`.
- **A TUI end-to-end test can flake.** `test_cd_moves_and_resumes` failed once in CI, with `/cd`
  sent while the previous prompt was still finishing, and passed on rerun.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.11.0
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.11.0` tag through the
existing release workflow. Because `0.11.0` is not a prerelease, PyPI's default install moves to
0.11.0.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.11 wisp-ai` and the same with
  `--python 3.12` on a native target each report `0.11.0` from both `wisp --version` and
  `wisp-tui --version`.
- [ ] In a real terminal, confirm the background-process changes:
  - a prompt that starts a background process shows it in the strip under the composer, and Down
    from an empty composer focuses it in the side panel;
  - Enter on the process shows its output in place, refreshing while it runs; `x` then `y` stops
    it; and it stays listed as stopped.
- [ ] Then confirm the MCP and codemode changes:
  - `/mcp` shows a server's read-only count, and `h` on a server with hinted tools lists them and
    marks them after confirmation;
  - with the `codemode` extra and an MCP tool marked `"read"`, `/codemode` reads "On for the next
    prompt" and counts the tool, under both `"mcp_tool_exposure": "direct"` and `"on_demand"`.
- [ ] Replace `0.11.0 — Unreleased` in the changelog with the publication date.

## Rollback

0.11.0 reads sessions 0.10.x wrote, and 0.10.1 opens sessions 0.11.0 wrote. This preparation
confirmed it: 0.10.1 continued a session 0.11.0 had started, and 0.11.0 continued it again
afterwards. No new field is persisted: a script's structured results reach no event or session.

To go back, run `uv tool install --force --python 3.12 "wisp-ai==0.10.1"`. Both `wisp` and
`wisp-tui` must report the same release.

- **Credentials and trust records** need no cleanup.
- **Settings format** is unchanged. Tools marked read-only through `/mcp` stay in the server's
  `tool_safety`, which 0.10.1 reads as before.
- **A `tui_keybindings` entry for `panel.background`** is rejected by 0.10.1 as an unknown
  action, so remove it before going back.
