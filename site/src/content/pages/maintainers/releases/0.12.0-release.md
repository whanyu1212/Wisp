# Wisp 0.12.0 release decision and checklist

Status: release preparation, November 16, 2026. This PR prepares the release; it does not create
`v0.12.0` or publish packages. The previous stable release is 0.11.0, published November 16, 2026.

## Release decision

0.12.0 is a minor release on 0.11.0. The Python distribution/runtime, Rust TUI and native Python
extension all use `0.12.0`. The supported platforms stay unchanged: Python 3.11+, native
`cp311-abi3` wheels for macOS arm64 and Linux glibc 2.28+ x86_64, plus the pure fallback wheel
and source distribution. The backend and frontend must be the same release.

The changes since `v0.11.0` are:

- **Reload supported settings while idle (#1048, #1051).** `/reload` updates provider/model/effort,
  context reserve, automatic compaction, web search, codemode and subagents from user and trusted
  project settings. Explicit session choices and CLI/environment precedence survive reload.
  Invalid or unreadable settings leave the active configuration intact. The report names the
  effective default model and refreshes an open codemode picker or side panel.
- **Keep compaction failure diagnostics (#1049).** A failed summary retains the provider's error
  message and diagnostics, so a transport failure is distinguishable from cancellation or
  another compaction failure. This improves diagnosis; it does not fix network outages.
- **Safe sidebar navigation and useful diffs (#1050).** Clicking Recent turns while the agent
  works reports a recoverable busy notice, preserving the active command and draft. Changed-file
  cards fetch the selected diff without depending on an available transcript card. Labels say
  whether an edit was recorded, rather than claiming unrecorded changes came from outside the
  session.
- **Documentation and verification (#1043–#1047).** The 0.11.0 changelog is dated, the site uses
  real session screenshots with context and clearer Python-install instructions, and browser
  verification rebuilds first with isolated parallel CI workers.

**Why a minor release:** the RPC contract gains the `reload` command and
`rpc.settings.reloaded` event, and the Python SDK gains `RpcController.reload()`. A 0.11 reader
rejects the new command/event, so clients must upgrade with the backend. Session files keep
`schema_version` 6. See [compatibility](../../reference/compatibility.md#wisp-012-compatibility).

Reload remains deliberately limited: MCP, credentials, safety policy, storage, connection/retry
settings, process waking and keybindings require a restart. It does not reload code, instructions
or environment files. Busy sessions reject reload. Hosts given an explicit embedded configuration
cannot reload settings from files. See the [settings reference](../../reference/configuration.md)
and [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md).

The Pi-inspired codemode expansion and evaluation roadmap in
[HY-546](https://linear.app/queryverse/issue/HY-546) is future work, not part of this release.

## Prepublication acceptance

- [ ] The exact preparation PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests and live RPC schema checks pass.
- [ ] Rust format, Clippy, workspace tests, build and Python/Rust terminal handoff tests pass.
- [ ] The Astro format/type checks, tests, build and release-route browser checks pass.
- [ ] Candidate wheels pass on macOS arm64 and manylinux x86_64, including installed-wheel smoke
  and exact Python/TUI/native-extension version consistency.
- [ ] The release dry run succeeds on the accepted commit and verifies all four distributions.
- [x] A deterministic fake-provider session was created in 0.12.0, continued by the installed
  0.11.0 package, then continued again in 0.12.0, retaining all three prompts and replies.
  This checks ordinary prompt replay; it does not cover every tool, image or compaction history.

The existing workflow's manual dispatch performs a dry run without publishing:

```bash
gh workflow run release.yml --ref chore/release-0.12.0
```

## Publication and public-install acceptance

After this preparation PR merges, publication requires a separately authorized `v0.12.0` tag
through the existing release workflow. Because this is not a prerelease, PyPI's default install
moves to 0.12.0 after publication.

- [ ] The tag points to the accepted commit and all release jobs succeed, including attestation,
  PyPI publication and GitHub release creation.
- [ ] PyPI and GitHub contain the expected four distributions and matching SHA-256 hashes.
- [ ] Outside the source checkout, fresh Python 3.11 and 3.12 native installs report `0.12.0`
  from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, change a reloadable setting while idle, run `/reload`, and confirm the
  effective setting changes; an explicit session selection remains selected. An invalid settings
  file leaves the active configuration usable, and a busy session refuses reload.
- [ ] With the side panel or `/codemode` picker open, reload a changed codemode setting and
  confirm the displayed state refreshes.
- [ ] Click Recent turns during an active response, then open a changed-file diff. Confirm there
  is no crash, the draft survives navigation, and the selected file's diff opens.
- [ ] A controlled compaction provider failure displays its original diagnostic; do not provoke
  real network failures or spend model tokens solely to check error formatting.
- [ ] Replace `0.12.0 — Unreleased` in the changelog with the publication date and preserve the
  old heading anchor, following the earlier release entries.

## Rollback

Session entry and event-envelope formats, credentials, trust and settings formats are unchanged
from 0.11.0. Reload reports are RPC replies, not new durable session-entry kinds. The ordinary
prompt round trip described above passed during preparation.

To return to the previous release, install `wisp-ai==0.11.0` with the desired existing extras.
Both `wisp` and `wisp-tui` must report 0.11.0. No new keybinding action needs removal for this
release. `/reload` is unavailable in 0.11.0, so restart to apply settings there; external RPC
clients must also revert to the matching schema bundle.
