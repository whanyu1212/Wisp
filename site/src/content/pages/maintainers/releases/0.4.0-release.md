# Wisp 0.4.0 release decision and checklist

Status: release preparation, October 25, 2026. This PR prepares the release; it does not create
`v0.4.0` or publish packages. 0.3.1 (published October 23, 2026) is the latest stable release.

## Release decision

0.4.0 is a minor release on 0.3.1. It keeps the platforms from the
[0.3.0 checklist](0.3.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
plus a pure wheel; Python 3.12+ is required. The Python distribution/runtime, Rust TUI, and native
Python extension use `0.4.0`; the existing backend/frontend version check continues to require a
matching release.

It is a minor rather than a patch release because the supported Python API changes and tool
behavior changes in ways callers can observe:

- **Python API.** `ToolContext` replaces five undocumented operation write fields with
  `write_constraint` (#845), under the documented
  [0.4 exception](../../reference/compatibility.md#deprecation-and-removal). Names in the
  unsupported `wisp.agent.harness` namespace were renamed or moved (#815).
- **Tool behavior.** `bash` runs commands in bash rather than `/bin/sh` (#827); the read-only file
  tools follow in-workspace symbolic links (#829); `edit`, `read`, and `grep` change how they match,
  continue, and clip (#819, #821, #823, #826).
- **Native extension.** The directory walk and gitignore matching move into `wisp._native` (#840,
  #841), and `find` and `grep` run in parallel when it is present (#842).

It changes no command, event, handshake, session, settings, credential, or trust format, so 0.3.x
and 0.4.0 read each other's sessions. See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass, including the native walk conformance and search tests run
  against the built wheel on macOS arm64 and manylinux x86_64.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.4.0
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.4.0` tag through the existing
release workflow. Because `0.4.0` is not a prerelease, PyPI's default install moves to 0.4.0.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.4.0` from both `wisp --version` and `wisp-tui --version`.
- [ ] On a native target, `python -c "import wisp._native as n; print(n.NativeWalk)"` succeeds in
  the installed tool environment, so `grep` and `find` use the native walk.
- [ ] In a real terminal, run a prompt that issues several `grep` or `find` calls in one turn and
  confirm they complete, and that a `bash` command using `[[ ]]` succeeds.
- [ ] Replace `0.4.0 — Unreleased` in the changelog with the publication date.

## Rollback

0.3.1 and 0.4.0 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.3.1"`; both `wisp` and `wisp-tui` must report
the same release. Code that adopted `WriteConstraint` must return to the five `ToolContext` fields.
