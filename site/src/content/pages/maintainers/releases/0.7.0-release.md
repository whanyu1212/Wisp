# Wisp 0.7.0 release decision and checklist

Status: release preparation, November 10, 2026. This PR prepares the release; it does not create
`v0.7.0` or publish packages. 0.6.1 (published November 8, 2026) is the latest stable release.

## Release decision

0.7.0 is a minor release on 0.6.1. It keeps the platforms from the
[0.3.0 checklist](0.3.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
plus a pure wheel; Python 3.12+ is required. The Python distribution/runtime, Rust TUI, and native
Python extension use `0.7.0`; the existing backend/frontend version check continues to require a
matching release.

It carries 33 merged pull requests (#916–#948). The main changes:

- **Images (#937–#948, HY-462).** Models that take images see them: pasted or dragged into the TUI
  composer, attached through RPC or the SDK, or returned by `read` for an image file. Each adapter
  sends them in its provider's own format, within a per-request image budget; text-only models get
  a short note instead. Images live in a content-addressed store beside the session files.
- **MCP tools on demand (#926, #928, #930, #931, #933, HY-433).** When a run's MCP tool
  definitions are large, the model gets `mcp_search`, `mcp_describe`, and `mcp_call` instead of every
  definition. This is now the default (`mcp_tool_exposure = "auto"`), chosen from the tool-use
  evals.
- **Tool output the model can act on (#918, #921, #936, #946).** Long `bash` output shows its start
  and its end; edit diffs carry the file's real line numbers; `edit` keeps a file's byte-order
  mark; the prompt says when a project has no instruction files.
- **Terminal UI (#922, #925, #927, #929, #932, #935).** `$EDITOR` editing of the draft and of a
  card's file, OSC 8 links, a 256- and 16-colour fallback, terminal title and background
  notifications, and motion cues. The TUI moves to ratatui 0.30.2, so building it from source now
  needs Rust 1.88.
- **Evals (#916, #917, #919, #920, #923, #924, HY-443).** A live tool-use eval runner, a scripted
  sequence layer, and recorded baselines, plus `wisp -p --timeout` and an `agent.started` `setup`
  record so a run's setup can be confirmed.

**Why a minor release.** The wire contract grows. `prompt`, `steer`, and `follow_up` accept
`images`, and many events gain fields (image references, edit locations, MCP targets, run setup).
A 0.6 reader rejects each of them, and the connect-time version check already refuses a mixed
backend and frontend. Two defaults also change what the model sees: MCP tool exposure and the
`bash` output preview. Session files keep `schema_version` 6, but 0.6.x cannot read everything
0.7.0 writes; see [Rollback](#rollback).

Each pull request went through the repository's automated review before merge, and #942–#945 also
had an independent review. The behavior that changes what the model sees was measured
with the tool-use evals before it became a default:

- on-demand MCP, which cut tokens per run by 76–77% with a 102-tool catalog;
- the `bash` preview, which cut tokens by 46–75% on long-output tasks;
- the no-instruction-files prompt, which removed a tool error seen in about half of the runs.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

Known limitations:

- **Gemini images are unverified live.** `scripts/live_image_smoke.py` passed for the OpenAI
  Responses API, Codex, xAI (Responses and Chat Completions), and Anthropic, and DeepSeek got notes
  as a text-only model should. Every Gemini request failed with an exhausted-billing error, so
  neither Gemini image format has reached the live API (HY-472). If Gemini rejects one, a Gemini
  user who attaches or reads an image gets a provider error rather than a note.
- **The tool-use evals ran OpenAI-family models only.** No Anthropic or Gemini model was in the
  eval runs that chose the new defaults.
- **Images are named, not drawn.** The TUI shows image labels; thumbnails are HY-450.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.
- [ ] Optional: rerun `scripts/live_image_smoke.py --only google` once Gemini billing is restored,
  and record the result on HY-472.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.7.0
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.7.0` tag through the existing
release workflow. Because `0.7.0` is not a prerelease, PyPI's default install moves to 0.7.0.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.7.0` from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, confirm that:
  - a pasted screenshot shows as a composer chip and reaches a model that takes images;
  - a `read` of a PNG shows `[image W×H png]` on its card;
  - the terminal title changes while a run works.
- [ ] Replace `0.7.0 — Unreleased` in the changelog with the publication date.

## Rollback

0.7.0 reads sessions 0.6.x wrote, but going back is not lossless. A 0.6.x Wisp refuses a 0.7.0
session that holds a successful `edit` or a proxied MCP call, and opens one that holds images
without them. Keep a copy of `~/.wisp/sessions` before upgrading if you may roll back.

To go back, run `uv tool install --force --python 3.12 "wisp-ai==0.6.1"`; both `wisp` and
`wisp-tui` must report the same release. Sessions started in 0.7.0 then stay readable only by
0.7.0. Settings, credentials, and trust records need no cleanup; 0.6.1 ignores the new
`mcp_tool_exposure` setting.
