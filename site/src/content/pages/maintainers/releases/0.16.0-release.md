# Wisp 0.16.0 release decision and checklist

Status: release preparation, November 21, 2026. This PR prepares the release; it does not create
`v0.16.0` or publish packages. The previous stable release is 0.15.0, published November 21, 2026.

## Release decision

0.16.0 is a minor release on 0.15.0. The Python distribution/runtime, Rust TUI, and native Python
extension all use `0.16.0`. Supported platforms stay unchanged: Python 3.11+, native `cp311-abi3`
wheels for macOS arm64 and Linux glibc 2.28+ x86_64, plus the pure fallback wheel and source
distribution. The backend and frontend must be the same release.

The changes since `v0.15.0` (`#1111`–`#1115`) deliver transcript copying, per-turn change summaries
with turn-filtered `/diff`, `delta`-style stateful diff syntax highlighting, richer approval prompts
with saved per-project command allow rules and mouse choice, and a refined default response style:

- **Transcript copy with OSC 52 fallback (#1111).** Adds `Alt+Y` (`transcript.copy_last_response`)
  to copy the last assistant response as raw source Markdown, extends Browse mode (`F6`) to select
  and copy individual messages and fenced/indented code blocks (`y`), and preserves OSC 52 clipboard
  fallback over SSH.
- **Per-turn change summaries and turn-filtered `/diff` (#1112).** Adds inline `+N −M in K files`
  totals to closing `╰` run-summary rows, `Alt+G` (`transcript.turn_diff`) plus click and Browse
  `Enter` to open `/diff` filtered to a turn's edited files, `a` to toggle turn/all changes, `<`/`>`
  to step across editing turns, active-pane focus headers, and cross-file `[`/`]` hunk stepping.
- **`delta`-style stateful diff syntax highlighting (#1113).** Highlights `/diff` against full
  `before`/`after` file sources (and inline diff cards over continuous old/new streams) so
  multi-line strings and block comments stay accurate across lines, recognizes `.ts`/`.tsx`/`.jsx`
  and `Makefile`/shell dotfiles, styles keywords bold and comments italic, and preserves readable
  syntax colors inside word-diff emphasis.
- **Richer approvals with inline previews, mouse choice, and saved command rules (#1114).** Renders
  inline diff previews for `edit`, numbered syntax-highlighted proposed content for `write`, and
  wrapped syntax-highlighted `$ command` previews for `bash`; adds fail-closed per-project command
  prefix allow rules (`~/.wisp/permissions/`, `command_prefix_project` scope, `revoke_command_rule`
  command and `RpcController.revoke_command_rule()`, scrollable rule revocation in `/permissions`);
  and enables paint-guarded single-click confirmation on approval choice rows.
- **Peer response style and Codex medium verbosity (#1115).** Tunes `DEFAULT_SYSTEM_PROMPT` for
  quiet tool execution, peer cadence, scannable `- **Short label:**` bullets, and inline file/symbol
  retention, and raises `openai_codex` `text.verbosity` from `"low"` to `"medium"`.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md).

**Compatibility:** session `schema_version` 6 and event-envelope format 1 are unchanged, and
`0.16.0` reads existing `0.15.0` sessions. Sessions containing `tool.approval.requested` with
`command_prefix` or `tool.approval.resolved` with `rule_id: "command_allow_rule_v1"` are rejected by
`0.15.0`. The live RPC bundle (`schemas/live-rpc/` and conformance fixtures) adds
`revoke_command_rule`, `"command_prefix_project"` on `ApprovalScope`, `"command_allow_rule_v1"` on
`ToolApprovalResolved.rule_id`, `ToolApprovalRequested.command_prefix`, and
`PermissionState.command_allow_rules`. Backend, frontends, and external RPC clients must match
`0.16.0`. See [compatibility](../../reference/compatibility.md#wisp-016-compatibility).

Known limitations:

- **Saved command-prefix rules only match simple single commands inside the workspace.** Compound
  commands (`&&`, `||`, `;`, `|`), redirections, subshells, variable expansions, env prefixes, POSIX
  shell reserved words/builtins, disallowed executables, and broad folders (`$HOME`) intentionally
  require manual approval.
- **Pending `write` approval previews show proposed content without a before-file diff.** Because
  the tool has not yet read disk state before approval, `write` previews render numbered
  syntax-highlighted proposed content rather than claiming a file creation or known before-state.
- **Real-terminal visual, mouse click, and OSC 52 checks remain manual gates.** Automated unit,
  conformance, render-buffer, and PTY handoff tests cover logic and rendering paths, while live
  terminal interaction remains a manual acceptance check below.

## Prepublication acceptance

Record CI and dry-run links in the preparation PR; unchecked items below remain publication gates.

- [ ] The exact preparation PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] Astro format/type checks, tests, build, and release-route browser checks pass.
- [ ] Candidate wheels pass on macOS arm64 and manylinux x86_64, including installed-wheel smoke
  and exact Python/TUI/native-extension version consistency.
- [ ] The release dry run succeeds on the accepted commit and verifies all four distributions.

The existing workflow's manual dispatch performs a dry run without publishing:

```bash
gh workflow run release.yml --ref chore/release-0.16.0
```

## Publication and public-install acceptance

After this preparation PR merges, publication requires a separately authorized `v0.16.0` tag
through the existing release workflow. PyPI's default install moves to 0.16.0 after publication.

- [ ] The tag points to the accepted commit and all release jobs succeed, including attestation,
  PyPI publication, and GitHub release creation.
- [ ] PyPI and the GitHub release contain the expected four distributions and matching SHA-256 hashes.
- [ ] Outside the source checkout, fresh Python 3.11 and 3.12 native installs report `0.16.0`
  from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, verify `Alt+Y` / Browse `y` copy, `╰` per-turn change totals + `Alt+G`
  turn-filtered `/diff` with `delta`-style syntax highlighting, inline `edit`/`write`/`bash`
  approval previews, single-click approval choice, and saving/revoking a command prefix rule in
  `/permissions`.
- [ ] Replace `0.16.0 — Unreleased` in the changelog with the publication date, keep the old
  `0160--unreleased` heading anchor, and add it to `site/tests/browser/releases.spec.ts`.

## Rollback

Install `wisp-ai==0.15.0` with the desired existing extras; both `wisp` and `wisp-tui` must report
`0.15.0`. `0.15.0` ignores `command_allow_rules` in `~/.wisp/permissions/`, but rejects sessions
written by `0.16.0` that contain `command_prefix` or `command_allow_rule_v1` approval events. Use
the `0.15.0` live RPC schema bundle for external RPC clients.
