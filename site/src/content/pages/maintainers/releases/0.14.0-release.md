# Wisp 0.14.0 release decision and checklist

Status: release preparation, November 19, 2026. This PR prepares the release; it does not create
`v0.14.0` or publish packages. The previous stable release is 0.13.0, published November 17, 2026.

## Release decision

0.14.0 is a minor release on 0.13.0. The Python distribution/runtime, Rust TUI, and native Python
extension all use `0.14.0`. Supported platforms stay unchanged: Python 3.11+, native `cp311-abi3`
wheels for macOS arm64 and Linux glibc 2.28+ x86_64, plus the pure fallback wheel and source
distribution. The backend and frontend must be the same release.

The changes since `v0.13.0` deliver graduated auto approval, new models, and tool/TUI improvements:

- **Auto edits and macOS Seatbelt Auto commands (#1068–#1071, #1073–#1076).** `/permissions auto`
  (`Auto edits`) grants atomic workspace/scratch edits on macOS and Linux (`workspace_edit_v1`).
  `/permissions auto-commands` (`Auto commands`) adds separately consented (`sandbox_commands_v1`)
  macOS Seatbelt containment with a read-only-workspace fast path for `pytest`/`unittest`/`npm test`/
  `cargo test` (with ancestor `Cargo.lock`), ephemeral per-command `TMPDIR`/`HOME`/`UV_CACHE_DIR`,
  isolated Cargo target caching (`CARGO_NET_OFFLINE=true`), temp-scoped Unix sockets,
  `PYTHONUNBUFFERED=1` with partial timeout output, macOS `O_SEARCH` traversal in `secure_fs`,
  safe combined short options (`-rN`, `-ra`, `-qq`, `-vv`, `-n4`, `-j4`, `git status -sb`),
  bounded independent no-tools command review, validated per-call Bash `cwd`, and automatic
  `poll`/`cancel` for owned sandboxed jobs.
- **Security hardening and real-binary TUI E2E validation (#1074–#1076).** Independent read-only
  security audits closed non-ASCII SBPL escaping, nested/Unicode/control symlink target-binding,
  `.venv`/`pyvenv.cfg` planting, cross-run ephemeral/Cargo-target isolation, `chmod`/`chflags`
  cleanup, and broad-root `bash.cwd` checks. Real-binary PTY E2E coverage verifies `wisp-tui` +
  RPC + Seatbelt on a standalone project. Known boundaries (pre-existing hardlinks, TCP
  localhost/network, PTY/`ps`, Linux/Windows `Auto commands`) remain explicitly documented.
- **GPT-6.2 Astra and Sol (#1067).** Registered for OpenAI API and Codex with API input ceiling
  enforcement.
- **Tool outcomes and terminal UI (#1064–#1066, #1072).** Explained tool failures and grouped
  outcomes, finished TUI selection bands and readable ANSI diffs, shared model/session picker
  dialog frames, and fixed a docs-search close/reopen race.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md).

**Compatibility:** session schema 6 and event-envelope format 1 remain unchanged. `0.14.0` reads
existing `0.13.0` sessions, but `0.13.0` rejects sessions containing `tool.approval.reviewed`
events or the new permission/audit fields. Back up sessions before upgrading if downgrade is
required. Saved `auto` / `auto_commands` permission defaults fail closed to `ask` on `0.13.0`.
See [compatibility](../../reference/compatibility.md#wisp-014-compatibility).

## Prepublication acceptance

Record CI and dry-run links in the preparation PR; unchecked items below remain publication gates.

- [ ] The exact preparation PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and live RPC schema checks pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] Astro format/type checks, tests, build, and release-route browser checks pass.
- [ ] Candidate wheels pass on macOS arm64 and manylinux x86_64, including installed-wheel smoke
  and exact Python/TUI/native-extension version consistency.
- [ ] The release dry run succeeds on the accepted commit and verifies all four distributions.
- [x] A session recorded in `0.13.0` format was loaded and continued by `0.14.0` with
  `tool.approval.reviewed` and `workspace_edit_v1` audit entries appended, and the strict
  event-decoding conformance suite verifies `0.14.0` Python/Rust parity.
- [x] Real-binary PTY E2E (`tests/tui_e2e/test_auto_permissions.py`) passes on a standalone
  project with `Auto edits` and macOS Seatbelt `Auto commands`.

The existing workflow's manual dispatch performs a dry run without publishing:

```bash
gh workflow run release.yml --ref chore/release-0.14.0
```

## Publication and public-install acceptance

After this preparation PR merges, publication requires a separately authorized `v0.14.0` tag
through the existing release workflow. PyPI's default install moves to 0.14.0 after publication.

- [ ] The tag points to the accepted commit and all release jobs succeed, including attestation,
  PyPI publication, and GitHub release creation.
- [ ] PyPI and GitHub contain the expected four distributions and matching SHA-256 hashes.
- [ ] Outside the source checkout, fresh Python 3.11 and 3.12 native installs report `0.14.0`
  from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, verify `/permissions` shows `Auto edits` and `Auto commands`, saves
  per-project consent cleanly, and executes routine workspace edits and (on macOS) fast-path
  sandboxed tests without human approval overlays.
- [ ] Replace `0.14.0 — Unreleased` in the changelog with the publication date and preserve the
  old heading anchor, following earlier release entries.

## Rollback

Install `wisp-ai==0.13.0` with the desired existing extras; both `wisp` and `wisp-tui` must report
`0.13.0`. Restore the pre-upgrade session backup when a session contains `tool.approval.reviewed`
or automatic-approval audit fields (`source`, `rule_id`, `auto_approved`, `approval_note`). Saved
`auto` or `auto_commands` records under `~/.wisp/permissions/` fail closed to `ask` on `0.13.0`
(or select `/permissions ask` to overwrite them). Use the older release's RPC schema bundle.
Credentials and trust formats are unchanged.
