# Wisp 0.9.2 release decision and checklist

Status: release preparation, November 13, 2026. This PR prepares the release; it does not create
`v0.9.2` or publish packages. 0.9.1 (published November 13, 2026) is the latest stable release.

## Release decision

0.9.2 is a patch release on 0.9.1. It keeps the platforms from the
[0.8.0 checklist](0.8.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
tagged `cp311-abi3`, plus a pure wheel; Python 3.11+ is required. The Python distribution/runtime,
Rust TUI, and native Python extension use `0.9.2`; the existing backend/frontend version check
continues to require a matching release.

It carries two user-facing changes:

- **A turn reads as one activity list (#1001).** In the terminal UI the `wisp` label appears only
  above text a reply writes. A reply that has not written text yet is led by its thought or
  working note, which stacks with the tool cards around it, and a finished reply that only called
  tools draws no rows. Reopened sessions no longer show a bare label before every tool step.
- **Compaction keeps more of long tool output (#1002).** The cut applied to each tool result before
  the summarizer reads it grows with the summarizer's budget, from 2,000 up to 20,000 characters,
  so with a typical window the middle of a long test run or file read reaches the checkpoint.
  Small and unknown windows keep 2,000. In the compaction evals, facts from the middle of long
  output survived in 166 of 168 checkpoints across seven models, up from none, for 4–27% more
  input per checkpoint.

#1002 also adds the compaction evals under `evals/compaction`, which ship in the source tree only,
and #1003 fixes a flaky terminal test. Neither changes the packages' behavior.

**Why a patch.** No command, event, handshake, session, settings, credential, or trust format
changes, and the live RPC schema bundle is unchanged, so 0.9.1 and 0.9.2 read each other's
sessions. The supported Python API is unchanged.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.9.2
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.9.2` tag through the existing
release workflow. Because `0.9.2` is not a prerelease, PyPI's default install moves to 0.9.2.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.9.2` from both `wisp --version` and `wisp-tui --version`.
- [ ] In `wisp-tui`, a prompt that calls tools shows the `wisp` label only above the reply's text,
  and reopening that session shows no bare label before its tool steps.
- [ ] Replace `0.9.2 — Unreleased` in the changelog with the publication date.

## Rollback

0.9.1 and 0.9.2 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.9.1"`; both `wisp` and `wisp-tui` must report
the same release. A checkpoint 0.9.2 wrote stays readable, since only how much tool output the
summarizer saw changed, not the checkpoint's format. Nothing on disk needs cleanup.
