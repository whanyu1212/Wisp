# Wisp 0.6.1 release decision and checklist

Status: release preparation, November 8, 2026. This PR prepares the release; it does not create
`v0.6.1` or publish packages. 0.6.0 (published November 7, 2026) is the latest stable release.

## Release decision

0.6.1 is a patch release on 0.6.0. It keeps the platforms from the
[0.3.0 checklist](0.3.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
plus a pure wheel; Python 3.12+ is required. The Python distribution/runtime, Rust TUI, and native
Python extension use `0.6.1`; the existing backend/frontend version check continues to require a
matching release.

It carries terminal UI changes only:

- **Default effort and footer notices (#908).** With no effort chosen, the composer and footer show
  the model's documented default, from a new optional `[providers.default_effort]` catalog table.
  Footer notices wider than their row scroll instead of being cut off.
- **One home per fact (#909–#912, HY-438).** The main column and the docked side panel no longer
  show the same facts: the panel drops its "Now" section and run label, YOLO moves to the composer
  line, the key hints merge into one footer row, healthy MCP servers and skills fold, Recent turns
  leaves out the pinned latest prompt, and turn summary rows name the mode and model only when they
  change.

It also fixes two CI checks that would otherwise block this release: the installed-wheel smoke
now recognizes the welcome screen #909 introduced (#913), and the live-progress terminal test
resubmits its prompt when a session-stats read refuses it (#912).

**Why a patch.** The only wire change is an optional `default_effort` field on the existing
`rpc.model_catalog` event's model entries. A 0.6.0 reader rejects it, but the connect-time version
check already refuses a mixed 0.6.0/0.6.1 backend and frontend, and the event is never persisted.
No event type, command, handshake, session, settings, credential, or trust format changes, so 0.6.0
and 0.6.1 read each other's sessions. External RPC clients that parse catalog events should move to
the 0.6.1 schema bundle with the backend. If that field should count as a contract change, release
this as 0.7.0 instead.

Each pull request went through the repository's automated review before merge, and #912 also had
an independent review. See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md)
for the full list.

Known limitations: compaction warnings in the footer still clip rather than scroll, and models
whose documentation names no default effort show `default`.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.6.1
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.6.1` tag through the existing
release workflow. Because `0.6.1` is not a prerelease, PyPI's default install moves to 0.6.1.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.6.1` from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal with the panel docked, confirm that the composer shows a model's default
  effort, healthy MCP servers and skills are folded, and a second turn's summary row leaves out
  the mode and model.
- [ ] Replace `0.6.1 — Unreleased` in the changelog with the publication date.

## Rollback

0.6.0 and 0.6.1 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.6.0"`; both `wisp` and `wisp-tui` must report
the same release. Rolling back restores the 0.6.0 layout and removes the default effort display;
nothing on disk needs cleanup.
