# Wisp 0.2.4 release decision and checklist

Status: release preparation, October 20, 2026. This PR prepares the release; it does not create
`v0.2.4` or publish packages. 0.2.3 (published October 20, 2026) is the latest stable release.

## Release decision

0.2.4 is a patch release on 0.2.3. It keeps the platforms from the
[0.2.3 checklist](0.2.3-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
plus a pure wheel. It changes no command, event, handshake, session, or trust format. The Python
and Cargo release-bearing packages use `0.2.4`; the existing backend/frontend version check
continues to require a matching release.

Since 0.2.3 it contains:

- **Codex timeout diagnostics and read-idle tuning** (#766). Transport failures retain safe,
  useful diagnostics and recovery guidance. The user-only `codex_read_timeout_seconds` setting,
  `WISP_CODEX_READ_TIMEOUT_SECONDS`, and SDK configuration allow positive finite read-idle limits;
  the default remains 300 seconds. Started responses are not automatically replayed. Completed
  tool results and partial replies remain available after resuming, but a model can still ask
  to repeat an action, so inspect completed results before repeating work.
- **Retained-edit review and theme refinements** (#767). Unified/split review, hunk and edit
  navigation, context toggling, syntax and word highlights, line gutters, and coherent folding
  make changes easier to inspect. Quieter tool rows, relative paths, task labels, and coordinated
  colors refine all nine existing themes. Paper remains the main light theme. Cumulative Git
  review is deferred; the overlay explicitly reviews one retained tool edit.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python formatting, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust formatting, Clippy, workspace tests, build, and Python/Rust handoff and benchmark PTY
  tests pass.
- [ ] Package version consistency and installed-wheel verification pass on the supported targets.
- [ ] `mdbook build book` succeeds without logged errors.

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.2.4` tag through the existing
release workflow. Because `0.2.4` is not a prerelease, PyPI's default install moves to 0.2.4.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.2.4` from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, browse an edit with F6 and Enter, toggle split/context with `s`/`c`,
  navigate hunks and edits, resize, and confirm that the review remains legible.
- [ ] Preview the existing themes with `/theme`, including Paper, and check diff readability.
- [ ] Confirm that Codex transport failures show useful diagnostics and that the configured
  read-idle timeout is respected without replaying an already-started response.

## Rollback

0.2.3 and 0.2.4 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.2.3"`.
