# Wisp 0.14.2 release decision and checklist

Status: release preparation, November 20, 2026. This PR prepares the release; it does not create
`v0.14.2` or publish packages. 0.14.1 (published November 19, 2026) is the latest stable release.

## Release decision

0.14.2 is a patch release on 0.14.0 and 0.14.1. Supported platforms stay unchanged: Python 3.11+,
native `cp311-abi3` wheels for macOS arm64 and Linux glibc 2.28+ x86_64, plus the pure fallback
wheel and source distribution. The Python distribution/runtime, Rust TUI, and native Python
extension use `0.14.2`; the existing backend/frontend version check continues to require a matching
release.

It carries two user-facing terminal UI changes:

- **Live status row with clickable `[stop]` (#1084).** The live status row above the composer
  gains animated 8-frame braille spinners (pinned to `⠋` under `MotionMode::Still`), active phase
  and tool elapsed timers, total run duration, live streamed output tokens (`⇣`), queued prompt
  count, width-invariant three-tier context usage colouring (`<70%` muted, `>=70%` warning,
  `>=90%` error), and a clickable `[stop]` button that highlights on pointer hover via `?1003`
  mouse-motion capture.
- **Shared dialog frame for remaining pickers and choice explanations (#1085).** The remaining
  TUI pickers and overlays (theme, logo, prompt history, session tree, queue, connection, skills,
  permissions, codemode, subagents, MCP, context, help, detail/script detail, file picker, and
  `Ctrl+G` key help) share `dialog.rs` and clickable hint footers, `/diff` uses the shared hint
  renderer, slash completion highlights matched characters in a full-width selection band with
  aligned descriptions, and approval, confirm-every-call, and trust decision panels show muted
  per-choice explanations that collapse to one-line choices on short screens.

#1083 tightens the root repository docs (`README.md`, `CONTRIBUTING.md`, `SECURITY.md`,
`.github/PULL_REQUEST_TEMPLATE.md`) and refreshes the banner wordmark without changing package
behavior, and #1082 dated the 0.14.1 changelog heading.

**Why a patch.** No command, event, handshake, session, settings, credential, or trust format
changes, and the live RPC schema bundle is unchanged, so 0.14.0, 0.14.1, and 0.14.2 read each
other's sessions. The supported Python API is unchanged.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

Known limitations:

- **Pointer-hover highlighting on `[stop]` requires `?1003` motion tracking.** Terminals or
  configurations without mouse capture or `?1003` any-event mouse tracking do not highlight
  `[stop]` on hover; standard SGR clicks and `Esc` remain available when hover tracking is
  unsupported.
- **Streamed output token counts (`⇣`) appear once token deltas arrive.** Before the provider
  emits output token deltas in a turn, no `⇣` counter is shown.
- **Decision choice explanations collapse on short screens.** Approval, confirm-every-call, and
  trust panels drop to single-line choices on short terminals to preserve key hints and action
  labels.
- **Real-terminal visual and hover checks remain manual gates.** Unit, render-buffer, and PTY
  handoff tests verify logic, `?1003h`/`?1003l` mode parity, and terminal output, while real
  terminal pointer hover, cleanup on exit, and visual polish remain manual checks below.

## Prepublication acceptance

Record CI and dry-run links in the preparation PR; unchecked items below remain publication gates.

- [ ] The exact preparation PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] Astro format/type checks, tests, build, and release-route browser checks pass.
- [ ] Candidate wheels pass on macOS arm64 and manylinux x86_64, including installed-wheel smoke
  and exact Python/TUI/native-extension version consistency.
- [ ] The release dry run succeeds on the accepted commit and verifies all four distributions.

The existing workflow's manual dispatch performs a dry run without publishing:

```bash
gh workflow run release.yml --ref chore/release-0.14.2
```

## Publication and public-install acceptance

After this preparation PR merges, publication requires a separately authorized `v0.14.2` tag
through the existing release workflow. PyPI's default install moves to 0.14.2 after publication.

- [ ] The tag points to the accepted commit and all release jobs succeed, including attestation,
  PyPI publication, and GitHub release creation.
- [ ] PyPI and the GitHub release contain the expected four distributions and matching SHA-256 hashes.
- [ ] Outside the source checkout, fresh Python 3.11 and 3.12 native installs report `0.14.2`
  from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal during an active run, verify the live status row spinner and timers,
  pointer-hover highlight and click on `[stop]`, and clean mouse-tracking teardown on exit.
- [ ] In a real terminal, verify `/` slash completion match highlighting and aligned
  descriptions, and shared dialog frames with clickable hint footers in `/theme`, `/mcp`,
  `/help`, and `Ctrl+G`.
- [ ] Replace `0.14.2 — Unreleased` in the changelog with the publication date, keep the old
  `0142--unreleased` heading anchor, and add it to `site/tests/browser/releases.spec.ts`.

## Rollback

0.14.0, 0.14.1, and 0.14.2 read each other's sessions. To go back, install `wisp-ai==0.14.1` with
the desired existing extras; both `wisp` and `wisp-tui` must report `0.14.1`. Nothing on disk
needs cleanup.
