# Wisp 0.10.0 release decision and checklist

Status: release preparation, November 14, 2026. This PR prepares the release; it does not create
`v0.10.0` or publish packages. 0.9.2 (published November 13, 2026) is the latest stable release.

## Release decision

0.10.0 is a minor release on 0.9.2. It keeps the platforms from the
[0.8.0 checklist](0.8.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
tagged `cp311-abi3`, plus a pure wheel; Python 3.11+ is required. The Python distribution/runtime,
Rust TUI, and native Python extension use `0.10.0`; the existing backend/frontend version check
continues to require a matching release.

It carries 11 merged pull requests (#1005–#1015). The main changes:

- **Background processes tell the agent when they stop (#1008, #1009, HY-535, HY-536).** A
  `bash` poll can wait for a process to exit with `until=exit`, so a watcher such as
  `gh pr checks --watch` no longer makes the model poll every few seconds. A process started with
  `notify_on_exit=true` puts its exit in front of the next prompt, and every exit is published as
  the new `process.ended` event.
- **Waking the agent (#1011, HY-537).** When such a process stops while the session is idle, the
  backend starts a run by itself that carries only the notice, at most three times between the
  user's prompts. After that a warning says auto-wake has paused (#1015). The
  `wake_on_process_exit` setting turns it off.
- **Seeing and controlling processes in the terminal UI (#1010, #1012, #1013, HY-536, HY-541,
  HY-538).** The side panel lists running processes, and a process that stops sends a desktop
  notification while the terminal is in the background. `/ps` lists them and `/kill` stops one
  without asking the agent. `Ctrl+B` moves the shell command the agent is waiting on to the
  background, and the side panel moves to `Ctrl+P`.
- **Hardening (#1015, HY-540).** A reopened session's cards for processes that no longer run read
  "no longer running" instead of staying on running. In-process SDK hosts do not wake the agent
  unless asked.
- **A scratch folder per session (#1006).** The agent writes pull request bodies and commit
  messages to a private folder the file tools can reach, instead of `/tmp`, which they refuse.
- **Homebrew bash on macOS (#1007).** Commands run in Homebrew's bash when it is installed, so the
  heredoc patterns `gh pr create` and `git commit` use stop failing under bash 3.2.
- **Terminal UI (#1005).** Each theme has its own startup logo gradient.
- **Tests (#1014, HY-539).** Fixed the in-process SDK shutdown tests that failed under parallel
  load.

**Why a minor release.** The wire contract grows. `cancel_process` and `background_tool_call` are
new commands; `process.ended` is a new event; the `rpc.state` reply gains `background_processes`
and message snapshots gain `process_wake`. A 0.9 reader rejects each of them, and the
connect-time version check already refuses a mixed backend and frontend. The terminal UI's side
panel key also changes. Session files keep `schema_version` 6; see [Rollback](#rollback).

**Waking is on by default in the CLI and terminal UI.** A wake run is billed to the user's
provider account while they may be away, so it is limited to three runs between the user's
prompts, uses the session's permission mode and approvals, and can be turned off with
`wake_on_process_exit` or `WISP_WAKE_ON_PROCESS_EXIT=0`. The setting is user-only. Applications
that embed Wisp in-process do not wake unless they turn it on.

See the
[changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

Known limitations:

- **Not tried by hand.** None of #1010–#1015 had a manual terminal check before this preparation;
  the acceptance list below covers them.
- **A reopened session can show two cards for one process.** If the session is reopened while a
  process still runs, a later poll of it starts a second card beside the history card. Its exit
  updates both.
- **The pause warning has no end-to-end test.** Unit tests cover when it is published, and it goes
  out the same way as `process.ended`.
- **`Ctrl+B` under tmux** needs pressing twice, because tmux uses it as its prefix key.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.10.0
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.10.0` tag through the
existing release workflow. Because `0.10.0` is not a prerelease, PyPI's default install moves to
0.10.0.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.11 wisp-ai` and the same with
  `--python 3.12` on a native target each report `0.10.0` from both `wisp --version` and
  `wisp-tui --version`.
- [ ] In a real terminal, confirm that:
  - a prompt that starts a background process with `notify_on_exit` lists it in the side panel,
    and its exit closes its card, sends a desktop notification while the terminal is in the
    background, and wakes the agent when the session is idle;
  - `/ps` lists the running processes, and `/kill` or selecting a panel row stops one;
  - `Ctrl+B` during a long foreground command ends the agent's call and keeps the command running,
    in a plain terminal and under tmux, and `Ctrl+P` toggles the side panel;
  - reopening a session whose processes stopped shows their cards as "no longer running".
- [ ] Replace `0.10.0 — Unreleased` in the changelog with the publication date.

## Rollback

0.10.0 reads sessions 0.9.x wrote, and 0.9.2 opens sessions 0.10.0 wrote. In 0.9.2, a prompt that
carried background-process notices shows the notice text in front of the prompt, and a prompt Wisp
sent by itself to wake the agent shows as a prompt holding only the notices.

To go back, run `uv tool install --force --python 3.12 "wisp-ai==0.9.2"`; both `wisp` and
`wisp-tui` must report the same release. Settings, credentials, and trust records need no cleanup;
0.9.2 ignores the `wake_on_process_exit` setting and leaves the `scratch` folder beside the session
files alone. A `tui_keybindings` entry for `run.background` is rejected by 0.9.2 as an unknown
action, so remove it before going back.
