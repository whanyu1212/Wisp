# Wisp 0.6.0 release decision and checklist

Status: release preparation, November 6, 2026. This PR prepares the release; it does not create
`v0.6.0` or publish packages. 0.5.0 (published October 27, 2026) is the latest stable release.

## Release decision

0.6.0 is a minor release on 0.5.0. It keeps the platforms from the
[0.3.0 checklist](0.3.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
plus a pure wheel; Python 3.12+ is required. The Python distribution/runtime, Rust TUI, and native
Python extension use `0.6.0`; the existing backend/frontend version check continues to require a
matching release.

It carries two features for long-running commands:

- **Saved output (#905, HY-434).** When a `bash` result has to cut output, the full stdout and
  stderr are saved in a private, bounded, per-process store, and the result names an `output_id`
  that the new read-only `read_output` tool pages through. Timed-out commands report saved output
  and their last lines.
- **Live progress (#906, HY-432).** A one-shot `bash` command reports its output while it runs
  through the new transient `tool.execution.progress` event, which the terminal UI shows beside the
  running card. Progress is never persisted and never reaches the model.

It is a minor rather than a patch release because it adds an event type, which a 0.5 frontend
rejects, and a tool, and because `bash` results and timeout errors change in ways callers can
observe. It also includes a terminal UI fix for the view jumping to a shortened reply's first row
(#896). It changes no command, handshake, session, settings, credential, or trust format, so 0.5.x
and 0.6.0 read each other's sessions. See the
[changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

Each feature's pull request received an automated review, and every finding was fixed with a
regression test before merge. An independent review of both features was started for this release
but stopped before it reported, so none is recorded here.

Known limitations: saved output does not survive restarting Wisp, and on Windows a saved file whose
command is still writing is deleted only when Wisp exits. The Windows limits deferred in HY-374
still apply.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass,
  including the terminal test that shows live progress before a result.
- [ ] The candidate wheel jobs pass, including the native walk conformance and search tests run
  against the built wheel on macOS arm64 and manylinux x86_64.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.6.0
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.6.0` tag through the existing
release workflow. Because `0.6.0` is not a prerelease, PyPI's default install moves to 0.6.0.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.6.0` from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, confirm that a command printing for several seconds shows its latest line
  beside the running card and its tail when expanded, and that a command printing more than the
  output budget names an `output_id` whose first page `read_output` returns.
- [ ] Replace `0.6.0 — Unreleased` in the changelog with the publication date.

## Rollback

0.5.0 and 0.6.0 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.5.0"`; both `wisp` and `wisp-tui` must report
the same release. Rolling back removes `read_output` and live progress; saved output in
`~/.wisp/tool-output/` is left for 0.6 to clean up, or can be deleted by hand.
