# Wisp 0.5.0 release decision and checklist

Status: release preparation, October 27, 2026. This PR prepares the release; it does not create
`v0.5.0` or publish packages. 0.4.0 (published October 25, 2026) is the latest stable release.

## Release decision

0.5.0 is a minor release on 0.4.0. It keeps the platforms from the
[0.3.0 checklist](0.3.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
plus a pure wheel; Python 3.12+ is required. The Python distribution/runtime, Rust TUI, and native
Python extension use `0.5.0`; the existing backend/frontend version check continues to require a
matching release.

It carries the tool hardening from the 2026-10-26 audit, including two security fixes:
protected-path matching now follows case-insensitive filesystems (#849), and `bash` commands no
longer inherit the provider API key variables (#850).

It is a minor rather than a patch release because tool behavior changes in ways callers can
observe:

- **Writes.** `write` and `edit` refuse an existing file the model has not read in the conversation,
  or one that changed since it did (#856); `edit` refuses files over 16 MiB (#863); `write` refuses
  targets that are not regular files (#859).
- **Commands.** `bash` withholds the provider key variables (#850) and bounds `timeout`,
  `lifetime_seconds`, `yield_seconds`, and `wait_seconds` (#857). Leaving a session stops its
  background processes (#864), and daemonized commands are stopped when the command ends (#854).
- **Searches.** `grep`, `find`, and `ls` stop after 30 seconds with partial results (#858), enter at
  most 100 directory levels (#863), and skip unreadable files and files with oversized lines
  instead of failing (#852, #860).

The supported Python API only gains fields (`ToolContext.withheld_environment` and
`ToolContext.seen_files`). It changes no command, event, handshake, session, settings, credential,
or trust format, so 0.4.x and 0.5.0 read each other's sessions. See the
[changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

Known limitations, deferred in HY-374: on Windows, commands are not stopped when the backend crashes,
`write` and `edit` overwrite existing files in place rather than replacing them atomically, and
`bash` runs commands in `cmd.exe`.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The macOS TUI handoff job, which fails the run since #870, passes on the accepted commit.
- [ ] The candidate wheel jobs pass, including the native walk conformance and search tests run
  against the built wheel on macOS arm64 and manylinux x86_64.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.5.0
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.5.0` tag through the existing
release workflow. Because `0.5.0` is not a prerelease, PyPI's default install moves to 0.5.0.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.5.0` from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, confirm that `bash` with `env` lists no provider key variable, that
  `edit` on a file changed by hand since the model read it is refused, and that a process started
  with `operation=start` stops when you start a new session.
- [ ] Replace `0.5.0 — Unreleased` in the changelog with the publication date.

## Rollback

0.4.0 and 0.5.0 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.4.0"`; both `wisp` and `wisp-tui` must report
the same release. Rolling back restores the 0.4.0 tool behavior, including `bash` commands that
inherit the provider key variables.
