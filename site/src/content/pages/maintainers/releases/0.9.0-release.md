# Wisp 0.9.0 release decision and checklist

Status: release preparation, November 13, 2026. This PR prepares the release; it does not create
`v0.9.0` or publish packages. 0.8.1 (published November 11, 2026) is the latest stable release.

## Release decision

0.9.0 is a minor release on 0.8.1. It keeps the platforms from the
[0.8.0 checklist](0.8.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
tagged `cp311-abi3`, plus a pure wheel; Python 3.11+ is required. The Python distribution/runtime,
Rust TUI, and native Python extension use `0.9.0`; the existing backend/frontend version check
continues to require a matching release.

It carries 14 merged pull requests (#981–#994). The main changes:

- **Subagents (#983–#987, #989, #990, HY-516, HY-526, HY-528).** An experimental `spawn_agent`
  tool: the model hands a list of read-only tasks to subagents, which run at the same time and
  return only their final reports. A call may start them fresh or fork the conversation. It is off
  unless turned on. `/subagents` turns it on, chooses the subagent model, and shows what each
  kind of subagent would get; a run warns when the chosen model is not on the provider.
- **Prompt cache on Gemini and Claude (#993, #994, HY-529, HY-530).** A new prompt no longer
  re-reads (Gemini) or re-writes (Claude) the previous run. Wisp saves the provider's own turn for
  each tool call and sends finished tool exchanges to later prompts as their run sent them. Live,
  the next prompt's first request went from 12% to about 89% cached on Gemini, and on Claude from
  reading 13,144 tokens and writing 21,897 to reading 32,099 and writing 348.
- **Gemini 4 Carbon (#992).** Google's newest model is in the catalog.
- **Startup (#991).** The terminal UI's backend connects MCP servers after it starts serving, so a
  resumed session's transcript does not wait for the slowest server.
- **Terminal UI (#988).** A slower startup logo entrance.
- **Housekeeping (#981, #982).** Agent instructions for any harness, and unused images removed.

**Why a minor release.** The wire contract grows. `get_subagents`, `set_subagents` and
`set_subagent_model` are new commands; `rpc.subagents`, `warning` and `mcp.status.updated` are new
events; tool results gain `model_usage`. A 0.8 reader rejects each of them, and the connect-time
version check already refuses a mixed backend and frontend. Session files keep `schema_version`
6, but 0.8.x cannot read everything 0.9.0 writes; see [Rollback](#rollback).

**Subagents are off by default.** The tool is marked experimental, and no run offers it until the
user turns it on with `/subagents`, the `subagents` setting, or `WISP_SUBAGENTS`. A subagent can
only read and search, never asks for approval, and cannot start subagents of its own. The setting
is user-only, because a subagent spends on the user's provider account.

See the
[changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

Known limitations:

- **Subagents are experimental.** Their limits (8 tasks a call, 4 at once, 63 tool rounds each, an
  8,000-byte report) and the tool's shape may change in a later release. Write access is not
  offered (HY-517).
- **Saved turns have gaps.** On Claude, a run steered mid-way still misses the cache from its
  tool-free response on, and a turn holding half of a web search is sent as text. Tool results
  with images in a replayed exchange are loaded but were not tested. Whether forked subagents
  benefit was not checked.
- **Session files grow** for Gemini and Claude sessions, which now store each tool-call turn. The
  growth was not measured.
- **Gemini 4 Carbon's catalog entry** takes its context window and prices from Google's pages as
  read on 2026-11-12, and records no default thinking level.
- **Gemini images are still unverified live (HY-472),** as in 0.8.0.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.9.0
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.9.0` tag through the existing
release workflow. Because `0.9.0` is not a prerelease, PyPI's default install moves to 0.9.0.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.11 wisp-ai` and the same with
  `--python 3.12` on a native target each report `0.9.0` from both `wisp --version` and
  `wisp-tui --version`.
- [ ] In a real terminal, confirm that:
  - `/subagents` opens the panel, `Enter` on the Subagents row turns them on, and the Model row
    lists the provider's models;
  - with subagents on, a broad question makes the model call `spawn_agent`, and the card shows
    each subagent's tool calls;
  - `/model` offers `gemini-4-carbon` under Google.
- [ ] Replace `0.9.0 — Unreleased` in the changelog with the publication date.

## Rollback

0.9.0 reads sessions 0.8.x wrote, but going back is not lossless. A 0.8.x Wisp refuses a 0.9.0
session that holds a subagent's result. Keep a copy of `~/.wisp/sessions` before upgrading if you
may roll back.

To go back, run `uv tool install --force --python 3.12 "wisp-ai==0.8.1"`; both `wisp` and
`wisp-tui` must report the same release. Sessions that used subagents in 0.9.0 then stay readable
only by 0.9.0; other sessions open in 0.8.1, which ignores the saved Gemini and Claude turns.
Settings, credentials, and trust records need no cleanup; 0.8.1 ignores the `subagents` and
`subagent_model` settings, which it does not know.
