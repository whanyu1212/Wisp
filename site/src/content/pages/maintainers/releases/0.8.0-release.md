# Wisp 0.8.0 release decision and checklist

Status: release preparation, November 11, 2026. This PR prepares the release; it does not create
`v0.8.0` or publish packages. 0.7.0 (published November 10, 2026) is the latest stable release.

## Release decision

0.8.0 is a minor release on 0.7.0. It keeps the native wheels for macOS arm64 and Linux glibc
2.28+ x86_64, plus a pure wheel, and lowers the Python floor to 3.11: the native wheels are now
tagged `cp311-abi3`. The Python distribution/runtime, Rust TUI, and native Python extension use
`0.8.0`; the existing backend/frontend version check continues to require a matching release.

It carries 24 merged pull requests (#951–#974). The main changes:

- **Codemode (#958, #960, #964, #968, #970–#973, HY-495).** An experimental `codemode` tool, from
  the new `codemode` extra: the model writes a Python script that calls the run's read-only tools,
  in monty's sandbox, and only what the script prints and returns comes back. It is offered by
  default when a run finds its MCP tools on demand; `/codemode` and `set_codemode` choose
  automatic, always, or never. Script cards show every call a script made, and sessions record
  them.
- **Moving a session (#951–#954, HY-475–HY-478).** `change_directory` and the TUI's `/cd` move a
  session's working directory, entering another project's configuration and trust when the folder
  is outside the current one. A trusted project's file tools reach its whole root.
- **Python 3.11 (#962, #965, HY-500, HY-504).** Wisp, its terminal UI, and the `codemode` extra
  install on Python 3.11.
- **Anthropic and `bash` (#957, HY-496).** Every Anthropic request that offered `bash` failed,
  because Anthropic rejects tool schemas with top-level `oneOf`. The adapter now sends them
  without top-level combinators.
- **Terminal UI (#956, #959, #961, #963, #966, #967, #969).** A welcome card with a working menu
  and an animated logo, verb-first tool lines, full-width selection and diff bands, heading
  colours, and a composer border that names the model, effort, and mode.
- **Evals (#955, #962).** Orchestration tasks and codemode baselines on the core coding tasks.

**Why a minor release.** The wire contract grows. `change_directory`, `get_codemode`, and
`set_codemode` are new commands; `session.directory_changed`, `rpc.codemode`,
`tool.nested.started`, and `tool.nested.ended` are new events; tool results and message snapshots
gain `nested_calls`, `nested_calls_omitted`, and `moved_to`. A 0.7 reader rejects each of them,
and the connect-time version check already refuses a mixed backend and frontend. Two defaults also
change what a run can do: codemode is offered when MCP tools are found on demand and the extra is
installed, and a trusted project's file tools reach beyond the working directory. Session files
keep `schema_version` 6, but 0.7.x cannot read everything 0.8.0 writes; see [Rollback](#rollback).

**Codemode is on by default, but only where it is installed.** The tool is marked experimental and
a plain `uv tool install wisp-ai` does not install monty, so no run offers it. Users who install
`wisp-ai[codemode]` get it in runs that find their MCP tools on demand. That default was chosen
from the orchestration evals: with tools found on demand, luna passed 23 of 25 runs instead of 17,
Sonnet and sol passed every run, and Sonnet's cost fell from $1.45 to $0.97. Each script call
passes the same checks as a direct call, and a call that would need an approval fails.

See the
[changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

Known limitations:

- **Codemode is experimental.** Its limits (200 calls, 2 minutes, 10 seconds of computing, and
  128 MiB per script) and its call surface may change in a later release.
- **Gemini images are still unverified live (HY-472),** as in 0.7.0.
- **Images are named, not drawn.** Thumbnails are HY-450.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.8.0
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.8.0` tag through the existing
release workflow. Because `0.8.0` is not a prerelease, PyPI's default install moves to 0.8.0.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.11 wisp-ai` and the same with
  `--python 3.12` on a native target each report `0.8.0` from both `wisp --version` and
  `wisp-tui --version`.
- [ ] In a real terminal, confirm that:
  - the welcome card's menu moves with `↑`/`↓` and opens a row with `Enter`;
  - after a reply, `/cd` to a subfolder draws the `── Working in <folder> ──` divider;
  - with `wisp-ai[codemode]` installed, `/codemode` reports the extra as available.
- [ ] Replace `0.8.0 — Unreleased` in the changelog with the publication date.

## Rollback

0.8.0 reads sessions 0.7.x wrote, but going back is not lossless. A 0.7.x Wisp refuses a 0.8.0
session that holds a codemode script's result, and opens one with directory moves but works from
its launch folder. Keep a copy of `~/.wisp/sessions` before upgrading if you may roll back.

To go back, run `uv tool install --force --python 3.12 "wisp-ai==0.7.0"`; both `wisp` and
`wisp-tui` must report the same release, and 0.7.0 needs Python 3.12 or newer. Sessions started in
0.8.0 then stay readable only by 0.8.0. Settings, credentials, and trust records need no cleanup;
0.7.0 ignores the `codemode` setting, which it does not know.
