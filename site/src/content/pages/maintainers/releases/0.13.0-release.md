# Wisp 0.13.0 release decision and checklist

Status: release preparation, November 17, 2026. This PR prepares the release; it does not create
`v0.13.0` or publish packages. The previous stable release is 0.12.0, published November 16, 2026.

## Release decision

0.13.0 is a minor release on 0.12.0. The Python distribution/runtime, Rust TUI and native Python
extension all use `0.13.0`. Supported platforms stay unchanged: Python 3.11+, native `cp311-abi3`
wheels for macOS arm64 and Linux glibc 2.28+ x86_64, plus the pure fallback wheel and source
distribution. The backend and frontend must be the same release.

The changes since `v0.12.0` complete the core codemode workflow:

- **Persisted script state (#1055).** JSON state commits with successful script results and
  survives restart, branching and compaction. Failed or cancelled scripts do not commit staged
  state; external effects from completed child calls are not rolled back.
- **Recoverable text and discovery (#1056, #1057).** Large text output can be read through output
  references during the process lifetime. Unified discovery supplies eligible built-in and MCP
  tool schemas and call guidance.
- **Policy and complete workflows (#1058, #1059).** File, shell and MCP child calls retain their
  normal policy and approval boundaries, audit records and cancellation behavior. Mutations are
  serialized; foreground work is cleaned up on cancellation. Subagents remain separate.
- **Presentation and prompt clarification (#1060, #1062).** Direct tools plus codemode remain
  the default. Codemode-only is opt-in, with direct-tool fallback when codemode is unavailable.
  Configuration, reload, RPC, SDK and TUI reports agree on the effective presentation. Prompts
  clarify return contracts, imports and reuse of saved state before refetching.
- **Evaluation (#1053, #1054, #1061, #1062).** Deterministic scenarios and live comparisons cover
  both presentations and codemode-off. The final 36-run evaluation passed 12/12 tasks in each
  codemode arm and 11/12 with codemode off; all 12 saved-state continuation checks passed. One
  codemode-only script recovered from a missing `asyncio` import. These runs are
  bounded evidence, not a general speed/cost claim or justification for changing the default.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) and
[final live report](https://github.com/whanyu1212/Wisp/blob/main/evals/tool_use/reports/2026-11-17-clarification-rerun.md).
[HY-546](https://linear.app/queryverse/issue/HY-546) and its stale core-workflow issues are closed
with explicit deferrals: images, durable output artifacts, model helpers and broader
provider/repetition confirmation remain future work.

**Compatibility:** the RPC codemode command/report gains presentation fields. Session schema 6
and event-envelope format 1 remain, but 0.12.0 rejects the new optional `codemode_state` field.
0.13.0 reads existing 0.12.0 sessions. Back up sessions before upgrading if downgrade is required.
See [compatibility](../../reference/compatibility.md#wisp-013-compatibility).

## Prepublication acceptance

Record CI and dry-run links in the preparation PR; unchecked items below remain publication gates.

- [ ] The exact preparation PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests and live RPC schema checks pass.
- [ ] Rust format, Clippy, workspace tests, build and Python/Rust terminal handoff tests pass.
- [ ] Astro format/type checks, tests, build and release-route browser checks pass.
- [ ] Candidate wheels pass on macOS arm64 and manylinux x86_64, including installed-wheel smoke
  and exact Python/TUI/native-extension version consistency.
- [ ] The release dry run succeeds on the accepted commit and verifies all four distributions.
- [x] A fake-provider session created with the `v0.12.0` source was continued by 0.13.0, retaining
  both replies. After appending a valid saved-state entry, the 0.12.0 reader rejected its new
  field. This source-level probe is not an installed-package or every-history compatibility test.
- [x] Saved-state resume, branch isolation, compaction and failed/cancelled-script tests pass.

The existing workflow's manual dispatch performs a dry run without publishing:

```bash
gh workflow run release.yml --ref chore/release-0.13.0
```

## Publication and public-install acceptance

After this preparation PR merges, publication requires a separately authorized `v0.13.0` tag
through the existing release workflow. PyPI's default install moves to 0.13.0 after publication.

- [ ] The tag points to the accepted commit and all release jobs succeed, including attestation,
  PyPI publication and GitHub release creation.
- [ ] PyPI and GitHub contain the expected four distributions and matching SHA-256 hashes.
- [ ] Outside the source checkout, fresh Python 3.11 and 3.12 native installs report `0.13.0`
  from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, confirm direct-plus-codemode is the default and an explicit codemode-only
  selection/reload is reflected accurately. Confirm direct tools remain available when codemode
  is unavailable.
- [ ] Save JSON state in a script, restart the session and load it without refetching. Recover
  a large text result before process exit. Confirm a denied child mutation does not execute.
- [ ] Replace `0.13.0 — Unreleased` in the changelog with the publication date and preserve the
  old heading anchor, following earlier release entries.

## Rollback

Install `wisp-ai==0.12.0` with the desired existing extras; both `wisp` and `wisp-tui` must report
0.12.0. Restore the pre-upgrade session backup when a session contains saved codemode state.
Do not strip state fields to force compatibility: subsequent results may depend on that state.
Older settings readers ignore `codemode_presentation`; remove it if no longer wanted. Use the
older release's RPC schema bundle. Credentials and trust formats are unchanged. Output
references are process-local and are not restored by a rollback or restart.
