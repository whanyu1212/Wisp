# Wisp 0.9.1 release decision and checklist

Status: release preparation, November 13, 2026. This PR prepares the release; it does not create
`v0.9.1` or publish packages. 0.9.0 (published November 12, 2026) is the latest stable release.

## Release decision

0.9.1 is a patch release on 0.9.0. It keeps the platforms from the
[0.8.0 checklist](0.8.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
tagged `cp311-abi3`, plus a pure wheel; Python 3.11+ is required. The Python distribution/runtime,
Rust TUI, and native Python extension use `0.9.1`; the existing backend/frontend version check
continues to require a matching release.

It carries one model catalog addition (#997):

- **Gemini 4 Hydrogen.** `gemini-4-hydrogen` joins the catalog with image input, a
  1,048,576-token context window, the `LOW`, `MEDIUM`, `HIGH` and `XHIGH` thinking levels (it
  rejects `MINIMAL`), a default of `HIGH`, and its standard prices, so `/model` offers it, its
  thinking levels are checked, and its cost is counted.

**Why a patch.** Only the bundled model catalog changes. No command, event, handshake, session,
settings, credential, or trust format changes, and the live RPC schema bundle is unchanged, so 0.9.0
and 0.9.1 read each other's sessions.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.9.1
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.9.1` tag through the existing
release workflow. Because `0.9.1` is not a prerelease, PyPI's default install moves to 0.9.1.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.9.1` from both `wisp --version` and `wisp-tui --version`.
- [ ] With a Google API key, `/model` lists `gemini-4-hydrogen`, and a prompt on it completes and
  reports a cost.
- [ ] Replace `0.9.1 — Unreleased` in the changelog with the publication date.

## Rollback

0.9.0 and 0.9.1 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.9.0"`; both `wisp` and `wisp-tui` must report
the same release. 0.9.0 passes `gemini-4-hydrogen` through to Google as an uncatalogued model, so a
session or setting that uses it still works, but `/model` does not list it and its cost is not
counted. Nothing on disk needs cleanup.
