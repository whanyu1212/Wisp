# Wisp 0.8.1 release decision and checklist

Status: release preparation, November 11, 2026. This PR prepares the release; it does not create
`v0.8.1` or publish packages. 0.8.0 (published November 11, 2026) is the latest stable release.

## Release decision

0.8.1 is a patch release on 0.8.0. It keeps the platforms from the
[0.8.0 checklist](0.8.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
tagged `cp311-abi3`, plus a pure wheel; Python 3.11+ is required. The Python distribution/runtime,
Rust TUI, and native Python extension use `0.8.1`; the existing backend/frontend version check
continues to require a matching release.

It carries one terminal UI fix (#977):

- **Footer keys.** Footer key hints were drawn on the panel colour. The footer is the terminal's
  last row, and terminals that extend edge cells into their window padding stretched each key's
  background into a block reaching the window's bottom edge. Keys are now bold body text with no
  background, wherever key hints appear.
- **Welcome card.** The card and its tip are centred in the conversation column instead of pinned
  above the composer, the tip is centred under the card, the menu's selection band spans the menu
  under the centred name rather than the whole frame, and the frame is drawn a step stronger.

**Why a patch.** Only the Rust TUI's drawing changes. No command, event, handshake, session,
settings, credential, or trust format changes, and the live RPC schema bundle is unchanged, so 0.8.0
and 0.8.1 read each other's sessions.

See the [changelog](https://github.com/whanyu1212/Wisp/blob/main/CHANGELOG.md) for the full list.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The candidate wheel jobs pass on macOS arm64 and manylinux x86_64, including the
  installed-wheel smoke on a fresh session.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.8.1
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.8.1` tag through the existing
release workflow. Because `0.8.1` is not a prerelease, PyPI's default install moves to 0.8.1.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.8.1` from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, confirm that the welcome card and its tip sit centred in the conversation
  column and the footer's keys show no blocks under them.
- [ ] Replace `0.8.1 — Unreleased` in the changelog with the publication date.

## Rollback

0.8.0 and 0.8.1 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.8.0"`; both `wisp` and `wisp-tui` must report
the same release. Rolling back restores the 0.8.0 welcome card and footer; nothing on disk needs
cleanup.
