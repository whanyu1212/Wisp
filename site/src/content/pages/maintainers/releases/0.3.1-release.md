# Wisp 0.3.1 release decision and checklist

Status: release preparation, October 23, 2026. This PR prepares the release; it does not create
`v0.3.1` or publish packages. 0.3.0 (published October 22, 2026) is the latest stable release.

## Release decision

0.3.1 is a patch release on 0.3.0. It keeps the platforms from the
[0.3.0 checklist](0.3.0-release.md): native wheels for macOS arm64 and Linux glibc 2.28+ x86_64,
plus a pure wheel; Python 3.12+ is required. It changes no command, event, handshake, session, or
trust format. The Python distribution/runtime, Rust TUI, and native Python extension use `0.3.1`;
the existing backend/frontend version check continues to require a matching release.

Since 0.3.0 it contains:

- **Automatic compaction status** (#810). The TUI run status line shows "Compacting context"
  while a threshold or overflow compaction runs inside a prompt, instead of "Working" or
  "Thinking". This is a frontend-only change; the backend already sent the compaction events.
- **Documentation site cutover** (#803–#809). The site builds with Astro instead of mdBook, adds
  Pagefind search, user-first navigation, refreshed entry pages, the published changelog, and
  the release record archive, and splits the TUI and SDK guides. It changes no runtime behavior.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python format, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust format, Clippy, workspace tests, build, and Python/Rust terminal handoff tests pass.
- [ ] The release dry run succeeds on the accepted commit, including candidate wheels,
  installed-wheel checks, version consistency, and the four distributions.
- [ ] The Astro build passes, including preserved routes, print anchors, and browser checks.

Run the existing Release workflow on the preparation branch:

```bash
gh workflow run release.yml --ref chore/release-0.3.1
```

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.3.1` tag through the existing
release workflow. Because `0.3.1` is not a prerelease, PyPI's default install moves to 0.3.1.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.3.1` from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, continue a session until automatic compaction starts and confirm the
  status line shows "Compacting context", then returns to "Working" once compaction completes.
- [ ] Replace `0.3.1 — Unreleased` in the changelog with the publication date.

## Rollback

0.3.0 and 0.3.1 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.3.0"`; both `wisp` and `wisp-tui` must report
the same release.
