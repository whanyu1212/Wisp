# Wisp 0.2.1 release decision and checklist

Status: release preparation, October 19, 2026. This PR prepares the release; it does not create
`v0.2.1` or publish packages. 0.2.0 (published October 19, 2026) is the latest stable release, and
the [0.2.0 checklist](0.2.0-release.md) records the decisions 0.2.1 keeps.

## Release decision

0.2.1 is a patch release on 0.2.0. It keeps 0.2.0's platforms (native wheels for macOS arm64 and
Linux glibc 2.28+ x86_64, plus a pure wheel) and every command, event, handshake, session,
settings, and trust format. The version is `0.2.1` in both the Python and the Cargo files.

Since 0.2.0 it contains:

- **Tool card chips, result connector, click to fold, and stacked cards** in the TUI (#759).
- **A closed partial reply** when a provider raises mid-stream (#753, HY-190) and **no
  `context.overflow` for a completed turn** (#758, HY-201). Both change which events a consumer
  sees in those failure paths, but not any event model.
- **A rejected repeated tool-call id** (#756, HY-191) and **one queue-full error for steers held
  before a run is ready** (#751).
- **Test-only changes** (#750, #752, #754, #755, #757).

Known flake, not a release blocker:
`test_rpc_pending_queue_is_bounded_while_prompt_is_blocked` in `tests/cli/test_rpc_mode_queue.py`
fails occasionally on CI. It failed on the 0.2.0 release commit too, before #751. Re-run a failed
job before treating it as a regression.

## Prepublication acceptance

- [ ] The exact PR head has terminal green CI and no actionable review threads.
- [ ] Python formatting, lint, configured mypy, full tests, and the live RPC schema check pass.
- [ ] Rust formatting, Clippy, workspace tests, build, and the Python/Rust handoff and benchmark PTY
  tests pass.
- [ ] `mdbook build book` succeeds without logged errors.

## Publication and public-install acceptance

After this preparation PR merges, publishing requires a separate `v0.2.1` tag through the existing
release workflow. Because `0.2.1` is not a prerelease, PyPI's default install moves to 0.2.1.

- [ ] The tag points to the accepted commit, and every release job succeeds, including attestation,
  PyPI publication, and the GitHub release.
- [ ] PyPI and the GitHub release have the four distributions, with matching SHA-256 hashes.
- [ ] Outside the source checkout, `uv tool install --force --python 3.12 wisp-ai` on a native
  target reports `0.2.1` from both `wisp --version` and `wisp-tui --version`.
- [ ] In a real terminal, tool cards show chips and the `└ ` connector, and clicking an action line
  expands and collapses it.

## Rollback

0.2.0 and 0.2.1 read each other's sessions. To go back, run
`uv tool install --force --python 3.12 "wisp-ai==0.2.0"`.
